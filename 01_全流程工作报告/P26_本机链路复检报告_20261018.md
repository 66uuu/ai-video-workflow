## 三、端到端实测（真出图 + 真出视频）

测试路径：Agent → `bridge/nr_bridge.py` → `http://127.0.0.1:8188` → GPU → 本地文件。
执行解释器：`ComfyUI\venv\Scripts\python.exe`。

### 3.1 文生图（t2i）

```bat
cd 11_本地工具接入指南\bridge
ComfyUI\venv\Scripts\python.exe nr_bridge.py t2i ^
  --prompt "a quiet empty street at night, light rain, street lamp glowing, cinematic lighting, 50mm, shallow depth of field, high detail" ^
  --negative "(worst quality, low quality:1.4), text, watermark, blurry, deformed" ^
  --width 512 --height 768 --steps 24 --seed 42 ^
  --out "..\_产出\link_test"
```

**结果：10 秒**，产出 `T2I_00002_.png`（512×768，568KB）。✔

### 3.2 图生视频（i2v，用上面这张图当首帧）

```bat
ComfyUI\venv\Scripts\python.exe nr_bridge.py i2v ^
  --image "..\_产出\link_test\T2I_00002_.png" ^
  --prompt "rain falls gently, the street lamp light flickers softly, quiet night atmosphere" ^
  --frames 17 --width 512 --height 768 ^
  --out "..\_产出\link_test"
```

**结果：115 秒**（日志逐秒轮询：首帧上传 → 目标 17 帧 → 生成 17 帧 → 完成），产出 `I2V_00008_.mp4`。
ffprobe 验证：`codec_name=h264, width=512, height=768, nb_frames=17, duration=0.708333, size=153911`。✔

### 3.3 实测速度基准（本机，供排产参考）

| 任务 | 耗时 |

## 四、发现的问题与处置

### ① 自研 NR_* 节点缺失 —— 不影响主链路

`ComfyUI-NightRoad` 节点包（NR_KenBurns / NR_Still / NR_ShotInfo / NR_SaveMP4）不在本工作包内，全包 grep 无源码，暂无法补装。

**影响范围裁定（已用源码引用检查证明）**：
- `09_工具脚本/` 全部业务脚本、`bridge/nr_bridge.py`、`example_business.py` **均不引用 NR_* 节点**（脚本中出现的 `NR_UPLOAD`/`NR_EP04_WAN` 仅为上传子目录名）；
- 官方自检 `selfcheck.py` 因这 4 个节点判"不能开工"，但这是**自检门过严**——按安装指南原话"没有也不影响主链路，只是少了'静帧推拉'这条降级路线"；
- **处置**：主链路（生图 / I2V / 合成）照常推进；KenBurns 静帧推拉路线暂不可用，需要时找回原始项目 `ComfyUI-NightRoad` 包。

### ② `09_工具脚本` 硬编码 E 盘路径 —— 本机不可直接用

该目录 bat/py 硬编码 `源机器E盘ComfyUI`、`源机器E盘灵异悬疑短剧_资产包\...`，而本机 ComfyUI 在 D 盘、**E 盘不存在**。

**处置**：本机一律走 `11_本地工具接入指南/bridge/` 零硬编码版本（config.json 已指向 `ComfyUI`，路径全 auto 探测）。本次实测即走此路线，无任何路径问题。若必须用 09 的 EP04 专用脚本，需先把三个硬编码路径改成 D 盘实际路径。

### ③ 存在并发用户（重要）

检测期间发现**另一个会话在同时使用同一台 ComfyUI**：12:19 仍在产出 `SWAP_*` 系列文件，GPU 被占约 4.3G。首次 72 帧 I2V 测试即因并发挤占 + 命令超时被 SIGTERM 失败（降低到 17 帧后成功）。

**处置（本机操作规范）**：提交大任务前先查队列——
```bat
curl --noproxy "*" http://127.0.0.1:8188/queue
```
队列非空就等或先用小任务；长任务一律用**后台运行 + 日志落盘**，避免前台超时被杀丢现场。

### ④ 显存与帧数红线（重申）

- 8G 卡：121 帧贴上限，**日常 72 帧**；帧数必须 **4n+1**（要 60 帧传 61，成片后 ffmpeg 裁回，`gen_len()` 已自动化）；
- **localhost 请求必须绕代理**（`curl --noproxy "*"` / bridge 内部已自动绕过），否则报 10061 极易误判"服务没起"。

## 五、本机生产操作流（最短路径）

```text
1. 确认服务：   curl --noproxy "*" http://127.0.0.1:8188/queue   → 有 JSON 即正常
2. 出图：       python nr_bridge.py t2i --prompt "..." --out <目录>
3. 出视频：     python nr_bridge.py i2v --image <上一步产出的png> --prompt "..." --frames 72 --out <目录>
4. 挂参考图：   先 --ref 走 build_t2i_ref（IPAdapter 保脸，模型已就位）
5. 批量/断点续跑/质检：照 bridge/example_business.py 样板改（零硬编码，推荐新一集用它）
```

Agent 侧只做"翻译"（把剧作意图写成提示词、帧数、验收标准、任务单），生成全部由本机 GPU 执行——**这就是本工作流"AI 操纵本地工具"的完整闭环，今日已实测成立。**
