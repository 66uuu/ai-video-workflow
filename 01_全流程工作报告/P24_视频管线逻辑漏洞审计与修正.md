# P24 · 视频管线逻辑漏洞审计与修正（EP04 → 全剧）

> 审计基准：`eternityspring/shuohao-skills` 的 `novel-storyboard`（三层结构 + 18 道确定性质量门）
> 与《夜路司机别回头》既有铁律（A/B/B2/C 章）交叉核对。
> 结论：**此前交付的"成片"在逻辑上不成立**。它不是短剧，是分镜图集配推拉。以下 15 条逐条给证据与修法。
> 审计日期：2026-10-17

---

## 一、审计口径

短剧的最小可交付单元不是"一张图 + 一个运镜"，而是：

```
集 → 段（一次视频生成，≤15s，不跨场）
      → 切（段内 2–5s，4n+1 帧 @24fps）
          → 分镜图（每切一张关键帧，钉在这一切 0.00s）
```

三条硬约束必须同时成立，缺一条就不叫短剧：

1. **切必须认领剧本节拍**，且认领节拍的台词秒数 ≤ 该切秒数；
2. **每一帧都是模型算出来的**（不是缩放出来的）；
3. **人物身份由参考图锁定**，正文不得再描述外观。

---

## 二、漏洞清单

### V1 · 静帧推拉冒充成片【致命】

- **证据**：`EP04_成片_技术验证版.mp4` 由 `NR_KenBurns` 生成，纯 PIL 缩放，零推理；相邻帧差仅 0.1–0.3。
- **根因**：以"能出片"替代"出好片"。
- **修法**：成片每一镜必须走 `Wan22ImageToVideoLatent → KSampler`，验收时强制做帧差量化（相邻帧差均值 < 0.30 判为滑片，退回）。

### V2 · 生成时长与时间轴不对齐【致命】

- **证据**：`run_ep04_wan.py` 里 `S24A.length = 121`（5.04s），而时间轴要求 2.5s；`S20A` 生成 5.04s 而时间轴 3.0s。S24A 实际输出 121 帧，剪辑时必须硬裁，音效与口型全部错位。
- **根因**：两套时基（时间轴 CSV / 生成脚本）各自为政，没有单一真源校验。
- **修法**：生成脚本改成**从 `EP04_timeline_v2.json` 读 `frames`**，禁止手写 length。Wan 要求 4n+1，故：

| 时间轴时长 | 目标帧 | 生成帧（4n+1） | 实际时长 | 剪辑取帧 |
|---|---|---|---|---|
| 2.0s | 48 | 49 | 2.042s | 取前 48 |
| 2.5s | 60 | 61 | 2.542s | 取前 60 |
| 3.0s | 72 | 73 | 3.042s | 取前 72 |
| 3.5s | 84 | 85 | 3.542s | 取前 84 |
| 4.0s | 96 | 97 | 4.042s | 取前 96 |

### V3 · 提示词里写了画风【严重】

- **证据**：`S20A` 正向尾部写"真实电影质感，浅景深，胶片颗粒"。
- **根因**：画风应由渲染层统一附加（全剧一套 LUT + 超分 + 颗粒），写进正文会与参考图既有画风打架，且逐镜措辞不同 → 逐镜画风不同。
- **修法**：正文删除一切画风词；画风统一在**后期链**（超分 → 统一调色 → 统一颗粒）完成。

### V4 · 提示词重复描述人物外观【致命，直接导致换脸】

- **证据**：`S20A` 写"穿米色风衣的女人"，`S24A` 写"中年男司机…极短寸头，两侧鬓角花白"。
- **根因**：外观描述与首帧参考图**竞争**。模型一部分听文字、一部分听图，两者不一致就取折中 → 脸漂、发型变。
- **修法**（`shuohao-skills` 明令）：**正文只写"通用身份"，不写长相、不写姓名、不写服装细节**。外观 100% 交给参考图。写"一个女人把手机贴在耳边"即可，不写风衣与发色。

### V5 · 写了模型画不对的微动作【严重】

- **证据**：`S20A` 写"眼皮眨了一下""重心换到另一只脚"。
- **根因**：眨眼的单帧微表情、重心转移这类细小动作，I2V 画不对，还会挤掉真正该演的那一下。
- **修法**：只写**几秒内能做完、模型见过千万次**的大动作：缓慢抬臂、转头、坐下、走过、放下手、攥紧。情绪外化为身体，不写形容词。

### V6 · 正文里写运镜【致命，已踩两次】

- **证据**：第一版 `S20A` 写"镜头极缓慢地向前推近"→ 第 4.9 秒人整个出画，画面变地面特写。
- **根因**：I2V 对运镜词极度敏感，会放大成大推镜。
- **修法**：**一切一个运镜**，写在 `motion` 字段并同时落进正文一句；正向固定追加 `CAM_LOCK`；负向显式禁 `推近/拉远/变焦/摇镜/平移/构图漂移/人物出画/裁掉头部`。

### V7 · 缺构图量化字段【严重】

- **证据**：31 镜只有"景别"一个词（近景/中景/特写），没有焦距、机位、构图法、视线落点、焦点、稳定性。
- **根因**：有分镜图时这些信息由图承担；一旦纯参考图出片，它们"就地消失"——表现为景别偏远、动作偏小、人物摆位随意。
- **修法**：每切补六个字段（`lens` / `cameraPosition` / `composition` / `eyeline` / `focus` / `stability`），写进正文对应句。

### V8 · 声音完全没有分层【致命】

- **证据**：成片**无音轨**。提示词里没有任何声音描述。
- **根因**：把声音当"后期再说"，但声景是**动作指令**——写了"雨丝持续落下"，模型才会真的画雨；不写，雨就是静止的贴图。
- **修法**：每切正文分三层写：① 台词/剧内音乐（角色听得见）② 声景（环境声、动作声、喘息、脚步）③ 配乐（角色听不见）。三层在提示词里各自成句。

### V9 · 动作幅度未按秒数预算【致命】

- **证据**：`S24A` 生成 5.04s，老周在第 4 秒左右**走出左边界**，末帧只剩空停车场与一只握录音笔的手。
- **根因**：写了"他从右向左走过画面"，但没算——2.5 秒的镜头塞一个"走过整个画面"，必然出画。
- **修法**：动作幅度必须与秒数匹配。"走过画面"只能用在 ≥4s 且机位跟随；2.5s 内只能写"侧身经过、肩膀擦过镜头前景"。**出画必须有叙事目的，否则算失误。**

### V10 · 镜头不认领节拍【致命】

- **证据**：31 镜各自有时长，但没有一镜声明"我覆盖剧本哪一场的哪几个节拍"。台词 20 句 41.8s 与 31 镜的对应关系靠人脑记。
- **根因**：跳过了"节拍认领"这一层，等于剧本与分镜之间没有对账。
- **修法**：每切补 `sceneIndex + beats:[起,止]`，脚本校验：每个节拍**恰好被一个切认领、按顺序、连续**；认领台词的估算秒数 ≤ 该切秒数。

### V11 · 表情变化没有来源【严重，与用户诉求直接相关】

- **证据**：`EX_LINYAN_表情差分板`（8 枚）、`EX_XIAOMAN`（3 枚）、`EX_AJI`、`EX_BAIXIANSHENG` 已产出并锁定，但 31 镜里**一镜都没用**。
- **根因**：把表情当成"模型自己会演"，实际上 I2V 不改表情基调——首帧什么表情，整段就什么表情。
- **修法**：**表情由首帧决定**。每切按情绪从已锁差分板里选帧作首帧；同一镜内不换表情。这是把"表情"与"运动"解耦的唯一可行做法。

### V12 · 场景与服装一致性无校验【严重】

- **证据**：`S23A` 车内暗红皮座（与 `SC_CARINT` 母版一致，可接受），但 `S24` 背景为白色出租车；两者并存未在设定书里写死，未来必被观众质疑。
- **根因**：缺少"同场同光同批"的批次约束。
- **修法**：按 `shuohao-skills` 的**生成批次单**归批：同场景 + 同光照的镜头共用同一张环境参考图，同一批连续生成；跨批必查色温。

### V13 · 占位素材混入【致命】

- **证据**：24 镜里 16 镜用别的镜头的图凑（`ph=True`），例如 S05/S12 用 `EP04_S01`、S10/S11/S14 用 `S16`。
- **根因**：等资产时先凑出片。
- **修法**：**占位素材不得进入任何交付版本**。补齐关键帧后才允许开拍该镜。

### V14 · 分辨率不达标【中等】

- **证据**：生成 512×768，交付要求 1024×1536。
- **修法**：定位为"生成在半分辨率、交付在目标分辨率"，中间必须有 **2× 超分**（Real-ESRGAN 或 ComfyUI 内置 upscale），且超分后需复核脸不变形。

### V15 · 无配音对齐单【严重】

- **证据**：`EP04_voice_records.tsv` 有 20 句台词与时长，但没有"这句贴哪一镜、从第几帧进"。
- **修法**：产出配音对齐单：`镜号 / 台词 / 起帧 / 止帧 / 说话人 / 音量`，TTS 与后期按此贴。

## 三、修正后的管线（EP04 起执行）

```
剧本（细纲六节拍）
  └─ 节拍认领 → 切（2–5s，4n+1 帧，一镜一运镜）
        ├─ 分镜图：从已锁资产 / 表情差分选帧（锁身份）
        ├─ 正文：通用身份 + 可完成动作 + 三层声音（不写画风/长相/运镜）
        ├─ 构图六字段：lens / cameraPosition / composition / eyeline / focus / stability
        └─ Wan22ImageToVideoLatent（帧数取自时间轴）
              └─ 超分 2× → 统一 LUT + 颗粒 → 配音对齐 → 拼接
```

**验收门（每条不通过不许交付）**

| 门 | 判据 |
|---|---|
| G1 时长对齐 | 每镜生成帧数 = 时间轴 `frames` 向上取到 4n+1 |
| G2 真运动 | 相邻帧差均值 ≥ 0.30 且首末帧差 ≥ 1.5 |
| G3 不出画 | 末帧主体仍完整在画（除非该镜设计即为出画） |
| G4 身份稳定 | 首/中/末帧与锁定锚点做脸部区域灰度相关 ≥ 0.86 |
| G5 无占位 | 源图均为该镜专属关键帧 |
| G6 声音完整 | 三层均有内容，成片有音轨 |
| G7 节拍全覆盖 | 每个剧本节拍恰好被一个切认领 |

## 四、与 shuohao-skills 的取舍

| 采用 | 不采用 | 原因 |
|---|---|---|
| 三层结构（段→切→分镜图） | MiniMax H3 提示词语法 | 我们用 Wan2.2，语法不同；取其方法论，不取其协议 |
| 节拍认领 + 台词装得下 | 15 秒段上限 | Wan TI2V-5B 单次上限约 5s，段上限改 5s |
| 六构图字段 | 同框 ≤3 人 | 本剧镜头多为 1–2 人，无需 |
| 生成批次单（同场同光归批） | Node.js 校验脚本 | 其脚本绑 H3 schema，我们另写 Python 校验 |
| 镜头正文协议无关写法 | — | 直接内化为本项目规范 |
| 配音对齐单 | — | 直接采用 |
