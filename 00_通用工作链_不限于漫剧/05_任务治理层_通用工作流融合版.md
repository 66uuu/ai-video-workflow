# 05 · 任务治理层：通用办公工作流 v5 × 视频管线（融合版 v5）

> 定位：`00_通用工作链` 原来只回答"**管线怎么跑**"（体检→出图→I2V→拼接）。
> 本文件补上另一半——"**需求怎么说到位、每一镜的提示词怎么写、AI 怎么交付才不算糊弄、出了问题怎么收敛**"。
> **v5 变化**（跟随通用办公工作流 v5 的「指令库 / 编号卡」）：
> ①指令层从"六类卡"扩为**镜级指令库**：一镜一卡，一张卡能独立成一次对话；
> ②角色由三角色扩为**四种角色不混用**（撰写 / 评审 / 审核 / 质量审查）；
> ③新增**章节型断言 B1–B8（视频版）**，与 U1–U8、C1–C6 并列；
> ④质量门仍十维、交付包仍六件，编号不重排；
> ⑤保留 v4 的事实底座、C 类断言、分级、双答一致性、错误压缩与交付落地。
> 机制来源见 `你的桌面\通用办公任务工作流\12_指令库_编号卡.md` 与 `07_附录_业界框架对照与v2升级说明.md`。

## 一、三层各管什么

| 层 | 回答的问题 | 内容 | 换题材 |
|---|---|---|---|
| **执行层（原有）** | 怎么出片 | 环境体检 → 出图 → 图生视频 → 拼接，见 `README.md` 与 `01_命令手册.md` | 不用改 |
| **指令层（v4 新增）** | 每一镜的提示词怎么写 | 事实底座 + K1–K6 编号卡 + 撰写/审查分角色，见本文件 G2.5 | 换数据，不换卡型 |
| **治理层（本文件）** | 怎么把需求说到位、怎么验收、怎么回炉 | 宪章 → 交底 → 澄清 → 指令卡 → 验收断言 → 分解 → 单步 → 一致性 → 质量门 → 收敛 → 交付 → 复盘 | 不用改 |

一句话：**执行层决定片子能不能出来，指令层决定每一镜有没有写对，治理层决定整片是不是你要的。**

## 三、十二道门（G0–G10，含 G2.5）


### G0 项目宪章（不变量，全程对照）

1. 帧数必须 **4n+1**（Wan2.2 硬要求），不满足不入队。
2. **一镜一意图**：一个镜头只做一件事，动作按秒预算。
3. I2V 提示词**不写**画风／长相／服装／姓名，身份由参考图承载。
4. 提示词**不写否定式、不写抽象情绪**；画面文字写"留白，无文字"。
5. I2V 结尾必须有**终止态**（停住／停下／不动了）。
6. 文件命名**唯一前缀**，防并行覆盖。
7. **不虚报**：没跑过的生成不写"已完成"，耗时与通过率未实测就标"未实测"。
8. **不替代**：AI 只给指令与检查清单，不代跑本机软件、不代签验收结论。

### G2.5 指令层（v4 新增：先有事实底座，再写卡）

> 为什么加这一层：v3 只管"验收有没有过"，但没说"每一镜的提示词该长什么样、谁写、谁审"。
> 结果是人一边写提示词一边验收，自己审自己，必然全过。这一层把"写"和"审"拆开。

| # | 块 | 填什么 | 现成来源 |
|---|---|---|---|

| 3 | 场景锁定表 | 场景码／主视觉路径／九宫格机位／本次复用哪一格 | `SC_*`、`MB_*`、`P05` |

|---|---|---|---|---|
| **K1 剧本卡** | 开新集 | 事实底座 1/2/6 + 上一集结尾 | 本集分场剧本（场次／节拍／钩子） | `07_提示词与剧本/EPxx_分集剧本.md` |

#### 2.5.3 一张卡的五件套（缺一不算卡）

| 零件 | 视频里怎么写 | 反例 |
|---|---|---|
| ① 角色 | "你是本片的分镜师／生图提示词工程师／I2V 运镜师" | "帮我写个提示词" |
| ② 粘贴占位 | 明确这一卡吃哪些输入：镜表行号、参考图路径、上一镜终止态 | 让人边写边翻文件 |
| ③ 编号问项（3–7 个） | "①主体是谁 ②动作几秒做完 ③终止态是什么 ④构图/景别 ⑤参考图挂哪张 ⑥负向词" | "写得专业点" |
| ④ 输出形式 | 固定三段：`【画面】/【光影/镜头】/负向：`；或固定运镜句式 | "随便什么格式" |
| ⑤ 负面清单（≥3 条） | 不写长相/服装/姓名；不写画风；不写"电影级/震撼"；不写否定式 | 只写"要什么" |

**K4 卡示范（可直接照抄）**

```text
你是本片的 I2V 运镜师。只写运镜，不写长相、服装、姓名、画风。
输入：镜号【S__】；关键帧【路径】；上一镜终止态【__】；本镜秒数【__】。
逐条回答：
① 起始画面是什么状态？（一句话）
② 这一镜只做哪一个动作？（一个）
③ 动作在几秒内完成？幅度到画面哪个位置停？
④ 终止态怎么写？（停住／停下／不动了）
⑤ 哪些词绝对不能出现？（长相/服装/姓名/画风/抽象情绪）
输出形式：
【运镜】……（一句，含起幅、动作、落幅）
【终止态】……
负向：不写人物外貌；不写镜头切换；不写两种以上动作
```

#### 2.5.4 四种角色，绝不混用（v5：三角色 → 四角色）

| 角色 | 只干一件事 | 禁止 |
|---|---|---|
| **撰写专家** | 按五件套产出该镜的 K3/K4 文本 | 不许自我评价、不许说"这条很好" |
| **评审专家** | 只挑毛病、给改法（动作是否做不完、终止态是否缺、参考图是否挂错） | 不许夸、不许重写 |
| **审核员** | 逐项核对要件（帧数 4n+1、命名唯一、卡号与镜号对齐） | 只输出"通过/待改"清单 |
| **质量审查员** | 整集跑统一质控，只诊断不重写 | 不许用"看起来不错"代替数值 |

**同一条指令里不能既写又评**——自己评自己，必然全过。

**配对规则**：K3、K4 每写完一镜，立刻跑同镜审查卡，审查记录追加到 `EPxx_卡片包.md` 末尾；**不留到整集写完再统一审**（那时错误已经复制了 24 遍）。

#### 2.5.5 镜级指令库模式（v5 新增，镜头多到一次写不完时切换）

> 适用判据：**每一镜能否独立成一次对话**。能 → 切卡跑；写完这镜还要反复回翻前文 → 说明卡没切对。

1. **先立事实底座**：按 2.5.1 六块一次填完，缺的标【待补充】，后续不再翻找。
2. **一卡一镜**：每镜一张 K3 + 一张 K4，格式固定为「角色 + 粘贴占位 + 3–7 个编号问项 + 输出形式 + 负面清单（≥3 条）」。
3. **写完立刻审**：同一镜的审查卡只输出"通过/待改 + 一句改法"。
4. **最后统一质控**：整集写完跑一次（事实 / 逻辑 / 对齐 / 表达 / 证据边界 五维），只诊断不重写。
5. **卡仍归 G3 管**：卡保证"这一镜写得像样"，不保证"整集达标"；U 与 C 断言照旧执行。

> 与 v4 的区别：v4 是"整集先写一批卡再统一审"，v5 是"一镜一卡一对话、写审交替"——避免同一个错误在 24 个镜头上重复。

### G3 验收断言（先写成可执行的，再动手）

每条用例必须写全四列，缺一列等于没写：

| 用例 | 断言内容 | 类型 | 阈值 / 判法 | 执行器 |
|---|---|---|---|---|
| U1 | 镜头数 = 分镜表行数 | 计数 | 一多一少都算 FAIL | 数文件 / 数 CSV 行 |
| U2 | 每镜帧数满足 4n+1 且 = 时间轴要求 | 数值 | 逐镜列出实际值 | `_qa_check.py <mp4> <帧数>` |
| U3 | 每镜"关键帧 + I2V 片段 + 命名一致"三件套 | 存在性 | 缺一即 FAIL | 目录核对 |
| U4 | 人脸/身材漂移达标 | 指标 | `drift_check.py` 末段 NCC ≥ 阈值 | `drift_check.py` |
| U5 | 文件前缀唯一，无同秒覆盖 | 唯一性 | 重复即 FAIL | 文件名去重统计 |
| U6 | 成片时长与时间轴误差 ≤【】 | 数值 | 建议 ≤ 0.3 秒 | `ffprobe -show_entries format=duration` |
| U7 | 镜头真运动且主体不出画 | 指标 | 相邻帧差 ≥0.30、首末 ≥1.5、边带 ≥首帧 55% | `_qa_check.py` |
| U8 | 交付包齐全 | 清单 | 成片 + 说明 + 时间轴 + 素材清单 + 验收单 + 卡包 | 目录核对 |

**卡级断言（v4 新增，管"写没写对"，与 U 并列）**

| 编号 | 断言 | 类型 | 判法 |
|---|---|---|---|
| C1 | 事实底座六块有值或标【待补充】，无空白项 | 字段齐全 | 逐项核对 |
| C2 | 每镜 K3 + K4 卡齐全（有对白再加 K5） | 存在性 | 镜号逐行对 |
| C3 | 每张卡五件套齐（角色/占位/编号问项≥3/输出形式/负面清单≥3） | 结构 | 逐卡打勾 |
| C4 | 负面清单零违反：K4 无长相/服装/姓名/画风；全文无"电影级/震撼/首次/填补空白" | 不含 | 搜词 |
| C5 | 每张撰写卡有对应审查记录（通过/待改 + 改法） | 存在性 | 看卡包末尾 |
| C6 | 卡与镜表一一对应（镜号无缺、无多、无重） | 计数 | 卡号集合 = 镜表行集合 |

**章节型断言（v5 新增，管"一镜一卡跑起来的留痕"，与 U/C 并列）**

| 编号 | 断言 | 类型 | 判法 |
|---|---|---|---|
| B1 | 事实底座六块全部有值或标【待补充】 | 字段齐全 | 逐项核对 |
| B2 | 每镜都声明"对应问项：__"，并逐条作答 | 存在性 | 看每张卡开头 |
| B3 | 负面清单零违反：不写长相/服装/姓名/画风/抽象情绪，不写第二个运镜 | 不含 | 搜词 |
| B4 | 每镜撰写与审查均留痕（撰写卡 + 审查记录） | 存在性 | 看卡包末尾 |
| B5 | 统一质控五维（事实/逻辑/对齐/表达/证据边界）全部作答 | 存在性 | 逐维核对 |
| B6 | 证据三级标注齐全（①资料直接支持 ②合理推断 ③待确认） | 一致性 | 抽查 10 句 |
| B7 | 参考图与资产编号一一对应（CH_* ↔ M_*/SC_*），无挂错、无一对多 | 一致性 | 资产索引比对 |
| B8 | 帧数与时长配额在 ±15% 内（4n+1 已满足后再算时长） | 数值 | ffprobe + 时间轴逐镜统计 |

> 凡 B 类有 FAIL，整集不得判 PASS；B3 / B7 两条是视频侧的硬红线。

**明确不做**：【不配音／不加字幕／不改剧本／不重绘角色设定】

写不到"能逐条打勾、能指名执行器"，不许开工。

> G3 是整套流程的地基：G7 的"对齐"维度拿 U1–U8 逐行对，"指令"维度拿 C1–C6 + B1–B8 逐行对。

### G4 任务分解（每步带完成判据与验证方法）

| 步骤 | 名称 | 输入 | 输出 | 完成判据 | 验证方法 |

| S2 | 指令卡 | 事实底座、剧本/分镜 | K1–K6 中适用卡 + 审查记录 | 每镜 K3+K4 齐，C1–C6 全过 | 对照宪章八条逐条过 |
| S3 | 关键帧出图 | K3 + 参考图 | 每镜 PNG | 张数 = 镜头数 | 抽查 3 张对提示词 |
| S4 | 图生视频 | 关键帧 + K4 | 每镜片段 | 每段帧数 4n+1 | `_qa_check.py` 读帧数 |
| S5 | 质检与重做 | 片段 + drift/qa 报告 | `重做清单.md/json`（机读） | 清单覆盖全部镜头；**清单内 FAIL 必须清零才能进 S6** | 抽 2 个不合格镜回查 |
| S6 | 拼接 | 合格片段 + 时间轴 + 重做清单 | 成片 mp4 | 时长误差达标；**出片脚本读清单，有 FAIL 直接拒绝** | ffprobe 读时长比对 |
| S7 | 交付打包 | 成片 + 时间轴 + 说明 + 卡包 | 交付包 | U8 六项齐全 | 目录核对 + 验收单签字 |

**规则**：一次只做一个 S；每步按"①本步输出 ②判据逐条打勾 ③三项自检 ④下游衔接"回报；不跳步。
**S2 的执行顺序固定**：事实底座 → K1 → K2 → 每镜 K3/K4（写一镜审一镜）→ K5/K6（按需）。顺序倒了就会"先写再找依据"。

### G5 单步下发（七要素）

1. **角色**：本轮你只做【S3 出图】，不做别的步骤
2. **输入**：只使用【贴入的 K3 卡/参考图路径】
3. **前置检查**：先列"本步需确认项"，缺失标"待补充"，不许猜
4. **逻辑链**：`读 K3 卡 → 核对参考图权重 → 检查 4n+1 与命名前缀 → 提交批量入队`
5. **负面清单**：K4 不得写长相/服装/姓名/画风；不得虚报已生成
6. **输出格式**：文件命名规则、输出目录、回报字段
7. **下游衔接**：末尾写"本步为 S4 准备了：__"

### G6 一致性检查（动手前跑一次）

- 宪章 ↔ 卡：有没有卡违反 G0 八条（尤其 4n+1、一镜一意图、I2V 不写长相）？
- 验收 ↔ 工作链：U1–U8 / C1–C6 每条是否至少被一个 S 覆盖？有没有 S 不服务任何断言？
- 工作链 ↔ 交底：每个 S 的输入是否都在"已有资产"里？缺的是否标"待补充"？
- 卡 ↔ 资产：每张卡引用的参考图路径是否真实存在？场景码是否在场景锁定表里？

**双答一致性（L3 交付级必做）**：三个关键数字由两条路径各算一次——
镜头数（数文件 / 数时间轴行）、总帧数（各镜之和 / ffprobe 实际）、总时长（时间轴预算 / ffprobe 实测）。
两路不一致 → 列分歧点，**不许取平均、不许取好看的那个**，追到哪个环节造成的再修。

### G7 质量门（十维 + 三态裁定）

| 维度 | 通用问法 | 视频专用判定 |
|---|---|---|
| 事实 | 有没有编造 | 没跑过的生成不许写"已完成"；耗时/通过率必须实测或标"未实测" |
| 一致性 | 是否自相矛盾 | 角色锁定图全程复用；I2V 不重复描述长相；三个关键数字双答一致 |
| 对齐 | 是否逐条回应验收 | U1–U8 逐条打勾，未过的写明原因 |
| 表达 | 有没有空话 | 不写"电影级质感""震撼" |
| 证据边界 | 结论分级 | ①实测 ②推断 ③待确认 |
| 格式 | 命名/路径/参数 | 4n+1、前缀编码、目录、批处理 label |
| 断言 | 断言有没有真跑 | U1–U8 每行填"实际值"，不许只写"已检查" |
| 一致性（双答） | 关键数字双答是否一致 | 镜头数/帧数/时长两路比对结果单列 |
| 交付 | 交付包齐不齐 | 成片 + 说明 + 时间轴 + 素材清单 + 验收单 + 卡包 |
| **指令（v4）** | 卡齐不齐、审没审 | C1–C6 逐条打勾；每镜 K3/K4 有审查记录 |

**裁定**：PASS（十维全过且断言全部实跑）／CONCERNS（有注意项，列明）／FAIL（有硬伤，列明并给修法）。

### G8 收敛循环（只补缺口，不整批重跑）

若 FAIL 或 CONCERNS：列缺口 → 对应哪条 U/C → 补哪个 S → 只重做坏的部分 → 再跑 G7；**最多 3 轮**，3 轮未收敛就停并输出"未解决项 + 建议人工处理"。

**错误压缩**：每次失败只写三件事——**一句原因 + 一条修法 + 影响哪条 U/C**。
同一个错误出现两次，必须换方法（换参数档 / 拆镜 / 换参考图），不许原样重试。

| 现象 | 先判 | 再动 |
|---|---|---|
| 人脸/身材漂移 | 看 `drift_check.py` 末段指标，定到具体镜头 | 只重做不合格镜头，其余保留 |
| 出片慢 | 是否逐条跑（模型反复卸载，约 71 秒/次） | 改批量入队（实测快约 3.2 倍） |
| 文件名互相覆盖 | 是否并行同秒完成 | 提示词最前面加唯一编码前缀 |
| 动作扭曲/出画 | 是否一镜多动作 | 拆成一个动作，结尾加"停住" |
| 帧数不对 | 是否 4n+1 | 重排帧数后重跑 `_qa_check.py` |
| 提示词"越写越像同一条" | 是否没写编号问项、只写一句描述 | 按 K3/K4 五件套重写，补终止态 |
| 审查总是全过 | 是否撰写/审查同一个人 | 换角色重审，只给"通过/待改 + 一句改法" |

### G9 交接单（长项目每 3–5 步一次）

已完成（对应哪些 U/C）／未决（卡在哪、需要谁给什么）／下一步（S 编号 + 输入是否齐）／关键路径与版本／已排除的错误方向。

### G10 交付落地

片子出来 ≠ 交付完成。交付包必须有六件，缺一件不算交付：

```
交付包/
├─ 成片.mp4                 ← 播放器能开、时长对
├─ 交付说明.md              ← 规格/镜头表/素材来源/已知限制
├─ 时间轴.csv               ← 帧数、时长、对应镜头
├─ 素材清单.md              ← 关键帧与源文件路径（可复现）
├─ 验收单.md                ← U1–U8 + C1–C6 逐条：实际值 / PASS-FAIL / 原因
└─ 提示词卡包.md            ← K2–K6 定稿 + 审查记录（下一集可复用/可重生成）
```

最后一步永远是你签收：**机器断言只能证明"符合约定"，证明不了"好看"**。

## 六、一页速查

1. **先分级**：试片走三道门，常规走全程，对外交付才加双答与人工终审
2. 开工先过 G0 宪章八条，再看 G1 六项交底 + 资料预取清单
3. G2 五项关键歧义没定，不许开工
4. **G2.5 先填事实底座六块，再写卡**：K3/K4 每镜一张，五件套缺一不算卡；镜头多时切"一镜一卡一对话"
5. **写的人和审的人分开**：四种角色不混用，写完一镜立刻审，只给"通过/待改 + 一句改法"
6. G3 验收写成 U1–U8 + C1–C6 + B1–B8，**每行都要有阈值和执行器**
7. G6 四方对一遍（宪章/卡/验收/资产），L3 任务再做关键数字双答
8. 每步七要素 + 完成判据 + 验证方法
9. 交付跑 G7 **十维**，给 PASS/CONCERNS/FAIL
10. 不通过按 G8 只补缺口，错误压缩，最多 3 轮
11. G10 交付包六件齐，验收单逐条填实际值
12. 长项目每 3–5 步出交接单，每批结束写复盘

## 七、版本演进（v3 → v4 → v5）

| 项 | v3 | v4 |
|---|---|---|
| 层数 | 执行层 + 治理层 | 执行层 + **指令层** + 治理层 |
| 提示词 | 靠人临时写 | **事实底座六块 + K1–K6 编号卡 + 五件套** |
| 角色 | 无明确分工 | **撰写 / 审查 / 质检三角色，写审分离** |
| 验收 | U1–U8 | U1–U8 + **卡级 C1–C6** |
| 质量门 | 九维 | **十维**（加"指令"） |
| 交付包 | 五件 | **六件**（加提示词卡包） |
| 错误处理 | 错误压缩 | 保留，并新增两条卡类故障 |

**v4 → v5（本版）**

| 项 | v4 | v5（本版） |
|---|---|---|
| 指令层形态 | 六类卡，整集写一批再统一审 | **镜级指令库：一镜一卡一对话，写审交替** |
| 角色 | 撰写 / 审查 / 质检 | **撰写专家 / 评审专家 / 审核员 / 质量审查员，四种不混用** |
| 断言 | U1–U8 + C1–C6 | U1–U8 + C1–C6 + **B1–B8（章节型）** |
| 质控节奏 | 整集写完统一质控 | **每镜审完即留痕 + 整集再跑一次五维统一质控** |
| 质量门 / 交付包 | 十维 / 六件 | 不变（编号不重排） |

**不采纳**：通用办公 V5 的 docx/xlsx/pptx 工具层（本包交付物是 mp4 / png）；
办公侧"论文分节"的章节术语（视频侧对应的是镜级卡，不搬术语）。
