## ⛔ 第 0 条铁律：产物一律落桌面，不回写本仓库

每完成一次任务，在桌面新建成果夹，产物只写那里：

```
你的桌面\AI产物\YYYYMMDD_任务名\{图片,视频,成片,日志}
```

```powershell
$env:IMG_OUT_ROOT="你的桌面\AI产物\20261024_任务名\图片"
$env:I2V_RAW_DIR="你的桌面\AI产物\20261024_任务名\视频"
$env:I2V_LOG_DIR="你的桌面\AI产物\20261024_任务名\日志"
```

本仓库只留工作流程、工具脚本、环境说明与工作日志；成片、原片、关键帧、资产图、任务单、审计报告**一律不进仓库**。
下方所有命令都在此前提下执行——命令里的仓库内路径只是历史默认值，照抄前先按上面三行覆盖。

## ⛔ 第 0.5 条铁律：一切落 D 盘，不碰 C 盘

- 成果、中间片、抽帧、日志、模型、缓存**全部在 D 盘**（桌面即 `你的桌面`）。
- C 盘只允许放**已安装的程序本体**（`.trae-cn\skills\prompt-optimizer`、ffmpeg 的 WinGet 目录）与系统临时目录；它们不是成果，不复制、不搬运。
- 禁止在 `C:\Users\...\AppData` 下自建目录长期存产物。
- 三个环境变量（`IMG_OUT_ROOT` / `I2V_RAW_DIR` / `I2V_LOG_DIR`）必须指到 D 盘；`bridge/config.json` 的 `output_dir` 已改为显式 D 盘路径，不再用 `auto` 落回仓库。

## 2. 出图

### 2.1 通用连接层：`nr_bridge.py t2i`

```bat
cd /d "<本包>\11_本地工具接入指南\bridge"
```

**纯文生图**

```bat
python nr_bridge.py t2i --prompt "1girl, portrait, soft daylight, 85mm" --out "..\_产出"
```

**挂参考图（保脸 / 保产品外观）**

```bat
python nr_bridge.py t2i ^
  --prompt "the same person standing in a bright studio, soft light" ^
  --ref "D:/refs/face.png" ^
  --ref-weight 0.5 ^
  --out "..\_产出"
```

**参数**

| 参数 | 默认 | 说明 |
|---|---|---|
| `--prompt` | 空 | 提示词。英文响应更好，中文也可 |
| `--negative` | 内置 | 负向词，不填用默认（只含技术缺陷项） |
| `--ref` | 空 | 参考图路径，正斜杠 |
| `--ref-weight` | 0.5 | 参考图权重 |
| `--width` / `--height` | 512 / 768 | 尺寸 |
| `--steps` | 0（用默认） | 步数 |
| `--seed` | 随机 | 固定种子可复现 |
| `--out` | `_产出` | 输出目录 |
| `--engine` | `sd15` | 生图引擎：`sd15` 快且能挂参考图 / `flux` 服从度高但不能挂参考图 |
| `--guidance` | 3.5 | 仅 FLUX 生效，schnell 蒸馏模型建议 3.0–4.0 |

**引擎切换：`--engine flux`（FLUX.1 schnell Q4_K_S GGUF，4 步）**

```bat
python nr_bridge.py t2i --engine flux --prompt "a rain-soaked index card on a metal desk, top light" --steps 4 --out "..\_产出"
```

本机实测（512×768，RTX 4060 Laptop 8G）：

| 引擎 | 步数 | 首次（含加载） | 热跑（服务端实测） | 能否挂 `--ref` 保脸 |
|---|---|---|---|---|
| sd15 | 28 | 12.49s | 6.3–6.4s | 能（IPAdapter） |
| flux | 4 | 30.5–34.1s | **约 3s** | 不能 |

> 判读提醒：ComfyUI 命中执行缓存时会回你 `0.00s`，客户端也可能在 0.3s 内返回。只认服务端 `user/comfyui_8188.log` 里的 `Prompt executed in X seconds`，别把缓存当提速。

结论：**人物关键帧仍走 sd15**（IPAdapter 是保脸的唯一手段）；**空景、道具、环境板走 flux**，热跑约为 sd15 的一半时间，且构图与提示词服从度更高。FLUX 不支持 `--ref`，传了会直接报错并提示改回 sd15。画风上两者都偏写实/电影感，厚涂剧漫风格仍需靠提示词强压或另换 LoRA。

**权重怎么选**

| 目的 | 权重 |
|---|---|
| 保主体 + 换场景 | 0.45–0.55 |
| 保主体 + 同场景换机位 | 0.70–0.80 |
| 只改表情/细节（构图不变） | 0.85–0.90 |

**注意**：参考图文件名不能含中文，否则 HTTP 400。

### 2.2 实例层：`gen_image.py`（批量任务单）

```bat
cd /d "<本包>\09_工具脚本"
python gen_image.py --jobs "IMAGES.json" --desktop
```

| 参数 | 作用 |
|---|---|
| `--jobs IMAGES.json` | 按任务单批量跑 |
| `--prompt "..."` | 单张跑（配合 `--ref`） |
| `--negative "..."` | 负向词 |
| `--width 768 --height 1152` | 尺寸 |
| `--steps 28` | 步数 |
| `--seed 0` | 0 = 随机 |

| `--desktop` | 出图复制到桌面 |
| `--only FF_S04,FF_S05` | 只跑指定 job id（任务单里筛） |

**`out` 字段**（可选）：任务单里写了 `out` 就按固定文件名落盘（首帧必须用，文件名要能被

EP04 的 15 张缺帧任务单在 `07_提示词与剧本\IMAGES_EP04_首帧.json`：

```bat
set COMFY_HOST=http://127.0.0.1:8188
python gen_image.py --jobs "..\07_提示词与剧本\IMAGES_EP04_首帧.json"
```

任务单格式（`IMAGES.json`）：

```json
{
  "jobs": [
    { "id": "IMG01", "mode": "t2i", "prompt": "【IMG01】your prompt", "negative": "" }
  ]
}
```

**`id` 必须写在提示词最前面**，否则并行同秒完成会互相覆盖，PNG 无元数据无法找回。

## 3. 图生视频（I2V）

### 3.1 通用连接层：`nr_bridge.py i2v`

```bat
cd /d "<本包>\11_本地工具接入指南\bridge"

python nr_bridge.py i2v ^
  --image "D:/keyframes/S01.png" ^
  --prompt "她缓慢地抬起头，然后停住。雨声持续。无配乐。近景，50mm，浅景深。" ^
  --frames 49 --profile std ^
  --out "..\_产出"
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `--image` | 必填 | 首帧图 |
| `--prompt` | 空 | 只写动作/声景/配乐/镜头，**不写画风** |
| `--frames` | 72 | 目标帧数（24fps → 49 帧 ≈ 2 秒） |
| `--profile` | 空 | `draft` / `fast` / `std` / `hq`，见 04 文档 |
| `--width` / `--height` | 档位或 512 / 768 | 生成尺寸（0 = 用档位值） |
| `--steps` | 档位或 24 | 步数 |
| `--sampler` / `--scheduler` | 档位或 euler / simple | 采样组合 |
| `--cfg` / `--shift` | 5.0 / 8.0 | 覆盖默认值 |
| `--max-frames` | 0 | 帧数上限，防止误跑 121 帧 |
| `--seed` | 随机 | 种子 |
| `--out` | `_产出` | 输出目录 |

**脚本内部自动做 4n+1**：要 49 帧会提交 49 帧（本身合规），要 72 帧会提交 73 帧再裁回。

**出多条别用命令行逐条跑**，用 Python 调 `run_many()`，能吃满「一次入队」的 3 倍加速：

```python
import nr_bridge as nb
c = nb.Comfy()
wfs = [nb.build_i2v(img, p, 49, **nb.PROFILES["draft"]) for p in prompts]
c.run_many(wfs, r"<D盘>\产出")
```

### 3.2 实例层：`batch_local.py`（按镜表批量）

```bat
cd /d "<本包>\09_工具脚本"
```

| 命令 | 作用 |
|---|---|
| `python batch_local.py` | **先全部入队，再依次收片**（推荐，快 3 倍） |
| `python batch_local.py --profile draft` | **草稿档：384×576 / 12 步，最快** |
| `python batch_local.py --submit-only` | 只压队列，立刻退出（压完可关终端） |
| `python batch_local.py --only S06,S08 --force --submit-only` | 压队列时**强制重提**已存在的镜（2026-10-24 修：以前 `--submit-only` 不认 `--force`） |
| `python batch_local.py --collect` | 只收片 + 质检，末尾自动写 `重做清单.md/json` |
| `python batch_local.py --collect --force` | 收片时**覆盖**已有原片（重跑后取新片用这个） |
| `python batch_local.py --qa-all` | **不连 ComfyUI**，只把现有原片全检一遍，写重做清单（改完片子先跑这个） |
| `python batch_local.py --qa-all --with-drift` | 同上，再补跑 NCC 漂移（只对通过运动质检的片子跑，约 20 秒/条） |
| `python batch_local.py --qa-all --with-drift --drift-fast` | 同上但**粗搜索（12/4）**，约 5–7 秒/条；31 镜全量实测约 2 分钟，日常复检用这个 |
| `python batch_local.py --redo` | **按重做清单自动重跑所有 FAIL 镜**（自动 --force；缺首帧的会先跳过并报出来） |
| `python batch_local.py --profile std --only S03,S07` | 指定档位 + 指定镜 |
| `python batch_local.py --only S16 --force` | 重做指定镜 |
| `python batch_local.py --list` | 只列清单 |
| `python batch_local.py --seed 20261018` | 指定种子 |
| `python batch_local.py --max-frames 72` | 帧数上限 |

**速度与画质的取舍见 `04_速度与一致性优化.md`。**

**为什么默认路径就快**：旧版是 `submit→等→submit`，两条之间的空闲期 ComfyUI 会把模型卸掉，
下一条又从零加载（约 71 秒）。一次性入队后模型常驻，第 2 条起每条只要 25 秒左右。
实测 24 镜：约 35 分钟 → 约 11 分钟。

`--submit-only` 的额外好处是**压完队列后 ComfyUI 自己跑，关掉终端也不影响**。

**只读盘 / 沙箱环境的两个出口**（2026-10-24 新增）：原片目录被系统设成「只能覆盖、不能新建」时，
`_raw_*.mp4` 与 `batch_*.log` 这类新文件会报 `Permission denied`。用环境变量把临时文件与日志改到可写盘即可：

```powershell
$env:I2V_RAW_DIR="<可写目录>\i2v_raw"    # 临时原片（收片后自动删）
$env:I2V_LOG_DIR="<可写目录>\i2v_logs"   # 批量日志
python batch_local.py --collect --force
```

成品仍然写回 `video_i2v\<镜号>_i2v.mp4`（已存在的文件允许覆盖）。

## 4. 拼接成片

### 4.1 通用：ffmpeg concat

先把每镜规格统一（分辨率、帧率、编码一致），再拼：

```bat
:: list.txt 里每行一个文件
:: file 'S01.mp4'
:: file 'S02.mp4'

ffmpeg -f concat -safe 0 -i list.txt -c copy out.mp4
```

规格不一致时先统一（示例：1024×1536 / 24fps）：

```bat
ffmpeg -i S01.mp4 -vf "scale=1024:1536:flags=lanczos" -r 24 -c:v libx264 -pix_fmt yuv420p S01_norm.mp4
```

### 4.2 实例层：`assemble_ep04.py`（按时间轴拼 + 打包）

```bat
cd /d "<本包>\09_工具脚本"
python assemble_ep04.py
```

| 参数 | 作用 |
|---|---|
| 无参数 | 全片；缺镜头则拒绝出正片，只出预览 |
| `--allow-partial` | 缺镜头也拼（中途看效果） |
| `--allow-bad` | 重做清单还有 FAIL 也硬拼（占位静止帧/出画会进正片） |
| `--native` | 不放大，保持 512×768 |
| `--no-desktop` | 不打包到桌面 |

它做四件事：**查重做清单** → 找片 → 规范化（1024×1536 / 24fps / yuv420p / 补静音轨 / lanczos 2×）→ concat → 打包桌面。

**为什么先查重做清单**：只要有 `重做清单.json` 且里面还有 FAIL，直接拒绝拼正片并列出镜号。
原因是"文件存在"不等于"能交片"——EP04 首轮实测 31 条原片里 15 条是占位静止帧，全拼进去就是一张图撑 15 个镜。

- 自动按配音单的 `预估秒` 回炉校准语速（最多 2 次，容差 ±10%）。实测 8 行旁白：首版 43.4s → 校准后 33.3s，每行落在 3.21–4.14s
- 产出：`lines/*.wav`、`voice_manifest.csv`、`voice_track.wav`、`voice_track.srt`
- `--no-fit` 关掉校准；`--timeline 时间轴.json` 可按镜号对齐（不做顺序累加）

| 参数 | 说明 |
|---|---|
| `--sheet` | 配音单 TSV，列名固定 10 列（**不是 `--script`**） |
| `--timeline` | 按镜号取起始秒；不给就顺序累加 + `--gap` |
| `--voice-map` | 按角色换音色，如 `"林砚=Microsoft Huihui Desktop"` |
| `--pitch-map` | 按角色变调不变速（半音，负数降调）。本机只有女声 Huihui，男角色靠降调近似，**只够对时，真音色要等 IndexTTS2 / CosyVoice** |

三个已修的坑（2026-10-23 实测）：

1. **同一镜里有两句会被镜号起点拽回去叠在一起**（S07 的"……没了。"与"撕的。"曾同秒起播）→ 现在第二句强制接在第一句尾部。
2. **`预估秒` 比镜头还长时会被硬压成超镜尾**（S14 写 4.2s，镜头只有 3.0s）→ 现在以镜头预算为准，塞不下会打印 `! 超出本镜`。
3. `--pitch-map` 必须在语速校准之后执行：校准只动 SAPI 的 Rate，变调不动时长。

**EP04 实测（20 行台词 / 3 个角色）**：

```
S02 林砚 3.00→5.89    S09 档案员 23.00→23.95   S14 档案员 36.89→39.34
...
整轨 88.14s / 24kHz 单声道 / 超镜尾仅 1 行（S13 超 0.09s）
```

注意 S14：原台词设计 4.2s，镜头只有 3.0s，压缩后 2.45s，语速偏赶——要么改台词，要么把这一镜加长。

**第二步：把音轨/字幕挂进成片（视频流不重编码）**

```bat
python mux_audio.py ^
  --video "..\_产出\EP04_无声版.mp4" ^
  --audio "..\_产出\配音_EP04\voice_track.wav" ^
  --srt   "..\_产出\配音_EP04\voice_track.srt" ^
  --out   "..\_产出\EP04_有声版.mp4"
```

| 参数 | 说明 |
|---|---|
| `--bgm` / `--bgm-volume` | 挂 BGM，循环到片长，人声 1.0、BGM 默认 0.15 |
| `--burn` | 烧录字幕（默认软挂 mov_text）；需 ffmpeg full build |
| `--ffmpeg` | ffmpeg 不在 PATH 时显式指定 |

两个已修的坑（照抄时别踩）：

1. **所有 `-i` 必须在 `-map` 之前**，否则报 `Error parsing options for input file`
2. **收尾用视频时长 `-t`，不用 `-shortest`**：字幕只有 32.3s 时，`-shortest` 会把 33.0s 的画面一起截短

实测（33.0s 测试片 + 32.3s 配音 + 字幕）：输出 h264 + aac 24kHz 单声道 + mov_text，时长 33.000s，画面零截断。

## 6. 测速与输出判读

### 6.1 测速（`bench.py`）

不知道自己的机器该用哪一档，先测一遍。它会按档位各跑一条，把耗时折算成"72 帧要多久"。

```bat
cd /d "<本包>\09_工具脚本"
python bench.py                                   :: 四档全测（默认每档 25 帧）
python bench.py --profiles draft,std --frames 33  :: 只测两档，片段更长更稳
python bench.py --dry-run                         :: 只打印计划，不真跑
```

输出：屏幕一张对比表 + 落盘 `_bench/bench_YYYYmmdd_HHMM.md`。

**判读**：看「折算 72 帧」那一列。
如果 draft 折算下来明显超过 260 秒（约 71 秒加载 + 72×1.27），说明链路有硬伤，
先去 `04_速度与一致性优化.md` 的「一之三、链路体检」逐项排查，别急着调参数。

### 6.2 运动 / 出画质检（`batch_local.py` 内置）

```
[S03] ✅ 72帧 | 相邻0.58 | 首末6.16 | 在画
```

| 指标 | 正常范围 | 异常处理 |
|---|---|---|
| 相邻帧差 | 0.3–2 | <0.05 **占位静止帧**（不是真生成，重提交）；0.05–0.3 几乎没动，重写动作；>8 运动过猛，可能出画 |
| 首末帧差 | ≥1.5 | 太小说明动作没完成或回到原点，加"停住" |
| 在画 | 是 | 否 = 主体走出画面，缩小动作幅度 |

**占位静止帧是最坑的一种**：文件存在、帧数也对、`assemble` 也会拼进去，但实际就是一张图撑时长。
`--qa-all` 会把它单独标成「占位静止帧」，并提示"加动作提示没用，要重新提交生成"。

**而且这些占位片是"借"别的镜的图凑出来的**（实测：抽 S05 的首帧，出来的是 S01 那张划痕报纸）。
所以**不要用"从占位片抽一帧当首帧"的办法救**——抽到的是别的镜的画面。
首帧只能真出图：跑 `一键生图.bat`，或在飞书表格里按 P13 生图卡下单。

### 6.3 主体一致性 / 漂移（`drift_check.py`）

专治"人脸身材会变"。逐帧和首帧做**位移对齐后的结构相似度**，
测的是"变形"而不是"走动"。

```bat
ComfyUI\venv\Scripts\python.exe 09_工具脚本\drift_check.py video_i2v\*.mp4
ComfyUI\venv\Scripts\python.exe 09_工具脚本\drift_check.py 某片.mp4 -v   :: 打印逐段明细
ComfyUI\venv\Scripts\python.exe 09_工具脚本\drift_check.py 某片.mp4 --fast :: 粗扫，快 4 倍
ComfyUI\venv\Scripts\python.exe 09_工具脚本\drift_check.py 某片.mp4 --json :: 机器读（batch_local 用这个）
```

```
文件                          帧数   末段NCC    ΔRGB   运动  判定
------------------------------------------------------------------
S03_i2v.mp4                    49    0.912      1.4   2.71  一致性好
S07_i2v.mp4                    49    0.641      5.8   4.02  主体变形 ←
```

| 末段 NCC | 结论 | 怎么办 |
|---|---|---|
| ≥ 0.85 | 一致性好 | 直接用 |
| 0.70 – 0.85 | 轻微漂移 | 短镜头可接受 |
| < 0.70 | 主体明显变形 | 重拍，或把帧数砍短 |

`ΔRGB` 持续单向增大 = 色调漂移（常见于低照度 + 高 shift）；
`运动` 接近 0 = 死片。

### 6.4 身份（脸）质检：`qa_identity.py`

`drift_check.py` 测的是"有没有变形"，测不出"这还是不是同一个人"。
`qa_identity.py` 用 **SCRFD 检测 + ArcFace 512 维特征** 直接比对身份，
权重是 ReActor 装好的 buffalo_l，**不需要 insightface 包、不联网**。

```bat
:: 只问"像不像"（绝对阈值）
ComfyUI\venv\Scripts\python.exe 09_工具脚本\qa_identity.py ^
  --ref "08_资产库\_资产锁定\M_LINYAN_面部锚点_v01.png" ^
  --target "08_资产库\EP04_关键帧\S13.mp4"

:: 推荐用法：加负样本，按"相对判据"裁定（不受打光/角度影响）
ComfyUI\venv\Scripts\python.exe 09_工具脚本\qa_identity.py ^
  --ref "08_资产库\_资产锁定\M_LINYAN_面部锚点_v01.png" ^
  --neg "08_资产库\_资产锁定\M_AJI_角色锚点_v01.png,08_资产库\_资产锁定\M_BAIXIANSHENG_角色锚点_v01.png" ^
  --target "08_资产库\EP04_关键帧\S03.mp4,S08.mp4,S13.mp4,S15.mp4" ^
  --csv "_产出\EP04_身份基线.csv"
```

`--target` 可以是单文件、目录、或逗号分隔的多个文件；`--frames 8` 是每条视频均匀抽 8 帧。

```
target                     抽帧    检出率   本人cos     前5均    最像别人      差值  裁定
S13.mp4                     8   100%   0.435   0.429   0.293   0.142  CONCERNS
S17.mp4                     8   100%   0.172   0.172   0.503  -0.331  FAIL
```

| 判据 | PASS | CONCERNS | FAIL |
|---|---|---|---|
| **差值**（本人cos − 最像别人） | ≥ 0.20 | 0.08 – 0.20 | < 0.08 |
| 本人cos（不给 `--neg` 时才用） | ≥ 0.55 | 0.40 – 0.55 | < 0.40 |

判读要点：

- **绝对余弦在这条管线上普遍偏低（0.40–0.45）**，不是"换脸"。
  实测同一个人：锚点对表情差分板 0.812，而 3/4 侧脸 + 低照度的实拍帧只有 0.42–0.44。
  所以**别用 0.55 卡镜头**，要看"差值"：S03/S13 差值 +0.12~+0.14，方向正确但强度偏弱 → CONCERNS 合理。
- 差值 **为负 = 画里这张脸更像别的角色**，基本可以判"这一镜没有本主"或"本主被挡住了"。
- 一帧里有多张脸时**逐脸都算，取最像本主的那张**（同框镜头里本主不一定是最大的脸）。
- 脸宽不足画宽 4% 的（海报、手机屏、远景小人）直接丢弃，避免误判。
- 裁定 FAIL 且备注"整段没检到脸"，先确认这一镜到底该不该有脸（空景、手部、道具特写属于正常）。

**已知边界**：负样本只认你给过的锚点。`CH_ARCHIVIST` 目前没有锁定锚点，
所以档案员镜头（S10/S14/S17）只能靠"跟其他角色都不像"间接判断——
这三个镜头实测差值 -0.08 ~ -0.33，说明画里的脸不是林砚，但**判不出是谁**。

## 7. 故障速查

| 现象 | 原因 | 修法 |
|---|---|---|
| `upstream connect failed` / `10061` | 没绕代理 | 加 `--noproxy "*"` |
| `comfyui.db.lock` | 已有实例在跑 | `netstat -ano \| findstr :8188` → `taskkill /PID x /F` |
| `No module named 'av'` | 用错 Python | 用 ComfyUI 的 venv python |
| `No module named 'google'` | 实为缺 protobuf | `pip install protobuf sentencepiece` |
| `SaveVideo missing 'format'` | format 传了 dict | 传字符串 `"mp4"` |
| HTTP 400 | 参考图中文名 | 改英文名 |
| 队列突然清空 | 重启了 ComfyUI | 重新 `--submit-only`，已出的会跳过 |
| 帧数差 3–4 帧 | 忘了 4n+1 裁切 | 用 `-frames:v` 不是 `-t` |
| 视频乱序 | 文件名没补零 | `S01`–`S09` 必须补零 |
| **每条都要等 80 秒以上** | 逐条 submit→等→submit，模型每条重载 | 用批量入队（`batch_local.py` 默认已改），或 `run_many()` |
| **加了 `--use-sage-attention` 起不来** | 本机没装 sageattention | 删掉该参数 |
| **保存节点报 `av.error.PermissionError [Errno 13]` / `PermissionError: ...output\...png`** | ComfyUI 是被后台任务/沙箱方式拉起的，对 `output`、`user` 目录全部写拒绝（连 Manager 缓存都写不了） | 由用户双击 `启动.bat`；或用 WMI 脱离拉起：`Invoke-CimMethod -ClassName Win32_Process -MethodName Create -Arguments @{CommandLine='"ComfyUI\venv\Scripts\python.exe" main.py --listen 127.0.0.1 --port 8188 --preview-method none'; CurrentDirectory='ComfyUI'}`。判据：起来后先跑一枪 `EmptyImage→CreateVideo→SaveVideo`，能落盘再正式跑批 |
| **`-vf subtitles=` 与 `-c:v copy` 同时用报 `Filtering and streamcopy cannot be used together`** | 烧录字幕必须重编码 | `mux_audio.py --burn` 已自动改用 libx264；手写命令时同样不能写 copy |
