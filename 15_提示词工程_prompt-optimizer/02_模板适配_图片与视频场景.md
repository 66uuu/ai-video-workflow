# 一、视频场景（7 个通用模板）

## 模板总表

| 模板 ID | 原名 | 视频场景用途 | 使用频率 |
|---|---|---|---|
| `user-prompt-planning` | 步骤化规划 | 一句话想法 → 分镜级结构化提示词 | ★★★★★ |
| `user-prompt-professional` | 专业优化 | 模糊描述 → 精确画面描述 | ★★★★★ |
| `iterate` | 通用迭代 | 已有提示词定向修改（质检不过返工） | ★★★★ |
| `general-optimize` | 通用优化 | 风格设定/角色系统提示词重组 | ★★★ |
| `user-prompt-basic` | 基础优化 | 快速消歧（轻度使用） | ★★ |
| `analytical-optimize` | 分析式结构优化 | 复杂场景深度重构（多角色互动） | ★★ |
| `output-format-optimize` | 带输出格式优化 | 对 JSON/参数结构有强要求的产出 | ★★ |

## 逐个定制说明

### 1. user-prompt-planning（步骤化规划）★主力

**什么时候用**：用户只有一句话想法时。例：「帮我做一个女司机夜班拉到怪乘客的镜头」。

**产出结构**（模板原生四段，视频场景这样填）：

```
# 任务：<镜头标题>
## 1. 角色与目标 → 这个镜头要完成什么叙事任务（如"让观众意识到后座的人不对劲"）
## 2. 背景与上下文 → 第几集、什么场景、前后镜头关系、参考图挂什么
## 3. 关键步骤 → 画面静态状态 → 一个变化 → 终止态（直接对应 I2V 四段式的 action）
## 4. 输出要求 → 格式=ComfyUI 就绪提示词包 JSON；风格=具体可视语言；约束=铁律 8 条
```

**定制点**：步骤 3 必须写成"静态→变化→终止"三段式，这是 Wan2.2 的动作语法。

### 2. user-prompt-professional（专业优化）★主力

**什么时候用**：用户有描述但太泛。例：「恐怖的隧道镜头，要吓人」。

**定制指令**（在模板原生指令后追加）：

> 优化时必须把抽象情绪词替换为具体画面元素：
> "恐怖"→具体动作/光影/构图；"吓人"→观众能看到什么。
> 画面描述按 [主体]+[动作/状态]+[场景]+[光影]+[镜头] 五段组织，缺的段不硬写。

**产出示例**：

- 原文：「恐怖的隧道镜头」
- 优化后：「夜，隧道口，一名女子站在路灯照不到的位置，只露出半边脸。她缓缓抬头看向隧道深处，停住。隧道内漆黑，只有远处一点昏黄灯光。逆光，人物呈剪影。固定机位，远景。」

### 3. iterate（通用迭代）★返工专用

**什么时候用**：提示词包已产出，但质检不过或用户要定向改。例：「动作太快了改慢点」「把镜头拉近」。

**铁律**（模板原生就有，视频场景再加一条）：

> 迭代只改指定方向，**其余部分一字不动**。
> 已有提示词里的帧数、参数、参考图指令不许在迭代中丢失。

**典型迭代对话**：

- 原词：「她快速转过身来」+ 需求「太快了」→「她极缓地转过身来，停住」
- 原词：「…中景。」+ 需求「拉近」→「…特写，只拍她的眼睛。」

### 4. general-optimize（通用优化）

**什么时候用**：写**风格设定/角色系统提示词**（不是单镜提示词）。例：给一个新项目定整体视觉方向。

**定制点**：产出的六段结构（Role/Profile/Skills/Rules/Workflows/Initialization）里，Rules 段直接填本工作流铁律，Workflows 段填"从想法到提示词"的六步 SOP。

### 5. user-prompt-basic（基础优化）

**什么时候用**：快速消歧。用户想法里有明显歧义词（"那个东西""有点怪"），先过一遍基础优化把话说全。

### 6. analytical-optimize（分析式结构优化）

**什么时候用**：复杂场景——一镜多角色互动、多物体关系。八段式（Role/Background/Attention/Profile/Skills/Goals/Constrains/Workflow/OutputFormat/Suggestions/Initialization）能把每个角色的动线分开写。

### 7. output-format-optimize（带输出格式优化）

**什么时候用**：批量生产提示词包时，要求产出严格符合 JSON schema（`positive/negative/frames/params/notes` 五字段）。在模板的 OutputFormat 段里写死本工作流的包格式。

# 二、图片场景（12 个图像专用模板）★ 2026-10-21 补充

## 2.1 图片侧模板总表

prompt-optimizer 的图像模板全部带 `templateType` 分类，按 **text2image / image2image / multiimage / iterate / 参考图** 五族划分：

| 模板 ID | 原名 | 图片场景用途 | 使用频率 |
|---|---|---|---|
| `image-general-optimize` | 通用自然语言优化 | 场景空镜/关键帧 t2i 生图的主力 | ★★★★★ |
| `image-json-structured-optimize` | 中文 JSON 结构化 | 生图需求→结构化 JSON（直接拆进 IMAGES.json） | ★★★★ |
| `image2image-general-optimize` | 通用编辑优化 | 关键帧定向修改（加/删/换/增强四意图） | ★★★★ |
| `multiimage-optimize` | 多图关系整理 | 多参考图保角色一致（锚点+差分+母版同场） | ★★★★ |
| `image-prompt-from-reference-image` | 参考图复刻 | 参考图 → JSON 复刻提示词（扒图建模板） | ★★★ |
| `image-prompt-migration` | 风格迁移 | 参考图版式 + 新主体内容 → 置入结果 | ★★★ |
| `image-iterate-general` | 通用迭代 | 生图返工定向改（JSON 进 JSON 出） | ★★★ |
| `image-chinese-optimize` | 中文美学优化 | 国风/水墨场景（本项目仅回忆段用） | ★★ |
| `image-creative-text2image` | 解构/创造性提示词 | 灵异实体概念发散（用完必须回炉） | ★ |
| `image-photography-optimize` | 摄影向自然语言优化 | ⚠️ 本项目禁用于成品图（见 2.2-10） | 禁用 |
| `image2image-design-text-edit-optimize` | 设计文案替换 | 海报/标题字换文案不跑版 | ★ |
| `image2image-json-structured-optimize` | 图生图 JSON 结构化 | i2i 需求 → 结构化 JSON | ★ |

## 2.2 逐个定制说明

### 1. image-general-optimize（通用自然语言优化）★主力

**什么时候用**：所有 t2i 生图的第一步。用户说"画一个午夜加油站"就丢给它。

**产出结构**（模板原生）：3–6 句自然语言，每句专管一个维度——

```
句1：主体+关键特征+动作+环境锚点
句2：光照来源+光质+时间+配色倾向
句3：氛围与情绪+抽象风格词
句4（可选）：材质与纹理
句5（可选）：构图/视角/画幅
句6（可选）：叙事张力
```

每个关键名词配 2–3 个精准修饰词（"柔和、漫射的晨光"而非"光线"）。

**定制点（视频/图片场景差异，重要）**：

> 模板鼓励"抓拍瞬间""正在……中"等**动态措辞**——这是给视频用的。
> **静帧关键帧必须反着来**：把动态词改成静止描述（"她握着手机站在那里"，不写"她正要拨号"）。
> I2V 要"一个动作+终止态"，t2i 要"一个姿势+定格"。

### 2. image-json-structured-optimize（中文 JSON 结构化）

**什么时候用**：生图需求复杂（多主体/多图层），或要直接生成可进管线的结构化数据。

**产出结构**（模板原生推荐结构）：

```json
{
  "场景": { "描述": "...", "主体": [...], "环境": {...}, "构图": {...}, "光照": {...}, "色彩": {...} },
  "约束": { "必须保留": [...], "避免": [...] }
}
```

**定制点**：`约束.避免` 数组**直接搬去 IMAGES.json 的 `negative` 字段**——一次优化，正负向全齐，不用再手写负面词。

### 3. image2image-general-optimize（通用编辑优化）

**什么时候用**：图已经生成了，要定向改。例：「把她的表情改成惊恐」「背景里加个人影」。

**核心机制（模板原生，本项目照用）**：先判**四意图**——

| 用户说法 | 意图 | 输出写法 |
|---|---|---|
| 描述了原图没有的元素 | **添加** | "添加XX，位置为…，与原图融合方式…" |
| "去掉/移除/删除" | **删除** | "移除XX区域，自然填补…" |
| "改成/换成/变成" | **替换** | "将XX区域替换为YY，其他不变" |
| "更/加强/突出" | **增强** | "增强XX的…，保持其他特征" |

**铁律**：用户提示词是"**期望的最终效果**"，不是"对原图的描述"；未提及的元素默认保留。

**定制点**：关键帧返工专用。改表情只写表情区，**构图/服装/光线一个字不许动**——否则整张重画，角色一致性崩。

### 4. multiimage-optimize（多图关系整理）

**什么时候用**：同一次生成要挂多张参考图——角色面部锚点 + 表情差分 + 场景母版，三图保一致出图。

**核心机制（模板原生）**：

- 用「**图1 / 图2 / 图3**」引用图片，**不发明角色名**
- 补全三件事：图片**关系**、**保留项**、**变化项与融合方式**
- 不假设图片内容，只围绕多图关系给可执行表达

**定制点**：与铁律 6（挂参考图不写长相/服装/姓名）**天然一对**——

> 身份信息（长什么样、穿什么）全部由图承载，文字只写"关系和变化"。
> 典型指令：「保留图1人物的面部特征与图2的表情，将人物置入图3的场景中，保持图3的光线与构图。」

### 5. image-prompt-from-reference-image（参考图复刻）★扒图神器

**什么时候用**：看到一张喜欢的图，想复刻成可复用提示词模板。产出即「重建指令」。

**产出格式（固定）**：

```json
{ "prompt": { ...结构化提示词... }, "defaults": { ...变量默认值... } }
```

**21 条强约束里与本项目最相关的**（模板原生）：

| # | 约束 | 对应当铁律 |
|---|---|---|
| 3 | 只写**有画面证据**的内容 | ↔ 铁律 2（不写抽象情绪） |
| 4 | **严禁** 8k / HDR / 光线追踪 / C4D / Octane / Unreal / Pixar / Disney / 电影级 / 超写实 / masterpiece / best quality | ↔ P00 禁套话 |
| 7 | 抽象词必须落地，后面必须接可见事实 | ↔ 铁律 2 |
| 11 | 姿态按可见事实写：宁写"手持手机垂在身侧"，不写"正在打电话" | ↔ 铁律 5（不补完整动作链） |
| 14–16 | 变量最多 3 个；只有角色设定图/海报/单主体插画类才变量化；变量优先序=主体称谓>一种主色>一项短文本 | — |

**定制点**：`defaults` 的变量位就是**下次换主角/换色的控制位**——复刻一次，量产一整组。模糊/边缘锚点保守命名（"远处建筑轮廓"，不补成"写字楼"）。

### 6. image-prompt-migration（风格迁移）★量产神器

**什么时候用**：手里有一张版式成熟的参考图（人设卡/双视图/海报），要把**新主体**置进这张模板。

**核心机制（模板原生）**：

1. 参考图 = 一张**近乎完整的图像模板**：主体数量与角色位、构图、场景、服装、道具、版式、光线、色调**默认全保留**
2. 当前提示词**只覆盖对应槽位**：明确写出的主体身份/数量/颜色/服装/道具/动作才替换
3. **版式骨架优先**：双视图/角色设定图/turnaround/海报**不许坍缩成普通单主体图**
4. 冲突时以当前提示词为准；提示词没给信号的槽位，以参考图为准
5. 允许拟人化融入，但新主体必须**一眼可辨**
6. 变量 1–3 个（提示词明确多槽位时最多 5 个）

**定制点**：漫剧量产的核心工具——

> 「用 P01 林砚人设图的版式，换成一个新角色」= migration，不是重新描述。
> 一张母版 + N 条主体提示词 = N 张同版式角色图。

### 7. image-iterate-general（通用迭代）

**什么时候用**：生图结果要定向改（视频侧 iterate 的图片版）。

**核心原则（模板原生）**：保持视觉意图与风格连续；**JSON 进必须 JSON 出**；最小必要修改——能改字段值就不改键名，能改局部就不整体重写。

**定制点**：与视频 iterate 同一条纪律——**只改指定方向，其余一字不动**。

### 8. image-chinese-optimize（中文美学优化）

**什么时候用**：国风/水墨/工笔场景。中式色彩材质（官绿、朱砂、宣纸、绢丝）、留白、对称、层次、季节意境。

**定制点**：本项目《夜路司机别回头》主line是都市悬疑，**只有回忆段/中式场景才用**；现代场景用了会串味。

### 9. image-creative-text2image（解构/创造性提示词）⚠️ 高风险

**什么时候用**：灵异实体（P07 特效包）的**超现实概念发散**——模板会把原始描述深度解构再奇幻重构。

**定制点（重要）**：

> 本项目主线是**接地气的写实惊悚**，这个模板的"颠覆视觉范式"倾向会毁掉 grounded 感。
> **只许用在灵异实体概念阶段，且产出后必须回炉**：过一遍铁律，把奇幻词落回具体可视元素，再进 IMAGES.json。

### 10. image-photography-optimize（摄影向自然语言优化）🚫 本项目禁用

**为什么禁**：模板面向摄影类图像生成，强调主体/构图/光线/色彩/氛围——但本项目铁律（用户 2026-10-06 明确要求）：**所有漫剧全是 2D 高清手绘动画风，禁止 CG 写实、照片级材质**。摄影向优化会把提示词带向写实渲染。

**唯一合法用途**：找**构图参考**时用（看它怎么组织画面层次），产出**不许直接进 IMAGES.json**；要进必须把所有摄影术语转译成绘画术语（`85mm 镜头`→`平视视角无透视变形`，`浅景深`→`平涂背景干净线稿`，`体积光`→`硬cel阴影`）。

### 11. image2image-design-text-edit-optimize（设计文案替换）

**什么时候用**：海报/封面/标题字的**文案更换**——保持配色、字体、字号层级、对齐、栅格不变，只换文字内容。

**定制点（边界说明）**：本铁律 3「画面不写中文文字」管的是**叙事画面**（角色生活的世界）；设计文案替换管的是**设计稿**（海报/标题字本来就有的文字层）。两者不冲突——前者防乱码，后者防跑版。

### 12. image2image-json-structured-optimize（图生图 JSON 结构化）

text2image JSON 模板的 i2i 版：图生图需求 → 严格 JSON（键名值全中文），保持原结构、原占位符。批量 i2i 返工时用，保证每次编辑指令结构一致、可 diff。

## 2.3 图片场景 vs 视频场景：关键差异

同一个想法做图还是做视频，走模板的路数不一样：

| 维度 | 视频（I2V） | 图片（t2i/i2i） |
|---|---|---|
| 动作描述 | 必须：一个动作 + 终止态 | 禁止：静态姿势定格（"站在那里"，不写"正要…"） |
| 帧数参数 | `frames` 4n+1（60→61） | 无帧数；给 `width/height/steps/cfg/seed` |
| 负向词 | 技术+一致性（防漂移/换脸） | 质量+内容（畸形/乱码/水印） |
| 参考图 | 挂图后文字**不写**长相服装姓名 | 挂图后文字**只写关系和变化**（图承载身份） |
| 时间/声音 | 要写（sound/music 段） | 不写 |
| 输出包 | `positive/negative/frames/params/notes` | `prompt/negative/mode/ref/尺寸/参数`（IMAGES.json 格式） |

## 2.4 图片侧铁律对照表

图像模板的强约束与本工作流 P00 铁律**同源**，互相印证：

| P00 铁律 | 图像模板里的对应约束 |
|---|---|
| 2 不写抽象情绪 | composition「抽象词必须落地，后面必须接可见事实」；general「每个关键名词配 2–3 个精准修饰词」 |
| 2 不写套话 | composition 第 4 条黑名单：8k/HDR/C4D/Octane/Unreal/Pixar/Disney/masterpiece/best quality |
| 6 挂图不写长相 | multiimage「身份由图承载，文字只写关系和变化」 |
| 5 动作按秒预算 | composition 第 11 条「姿态按可见事实写，不补完整动作链」 |
| 8 终止态（视频独有） | 图片侧对应物：**静态定格**（i2i 编辑只改指定区域） |

# 三、模板选择决策树（图片 + 视频合并）

```
用户给了什么？
├─【视频】一句话/一段话的想法
│   └─ user-prompt-planning → 铁律注入 → 就绪提示词包（五字段）
├─【视频】有描述但太泛/太抽象
│   └─ user-prompt-professional → 铁律注入 → 就绪提示词包
├─【视频】已有提示词 + 修改意见
│   └─ iterate（只改方向，别的不动）→ 铁律复查 → 新提示词包
├─【视频】风格设定/角色系统提示词
│   └─ general-optimize → 产出自带铁律的设定提示词
├─【视频】批量产出/严格 JSON
│   └─ output-format-optimize → 严格五字段包
├─【图片】一句话/一段描述，要画新图（t2i）
│   └─ image-general-optimize → 静态化处理（去动态词）→ 铁律 → IMAGES.json 任务
```
