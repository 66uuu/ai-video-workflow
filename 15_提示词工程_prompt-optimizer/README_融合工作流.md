# 15 · 提示词工程（prompt-optimizer 融合版）

> 本目录把 **prompt-optimizer 提示词优化引擎** 融进原有视频/图片生成管线，
> 解决一个老问题：**AI 直接写提示词，不精确、不完整，生成的视频/图片不符合要求。**
> 融合日期：2026-10-21（图片侧模板补充：2026-10-21）
>
> **覆盖范围：图片（t2i / i2i / 多图参考 / 参考图复刻 / 风格迁移）+ 视频（I2V）两类生成场景全覆盖。**
> 引擎侧 19 个模板（7 通用 + 12 图像专用）全部有场景化定制，见 `02_模板适配_图片与视频场景.md`。

---

## 一、为什么融合

**旧流程**（融合前）：

```
用户想法（一句话，模糊） → AI 直接写提示词 → ComfyUI 生成 → ❌ 不符合要求 → 返工
```

问题出在中间那一步：AI 写提示词靠"现场发挥"，用户的真实需求（情绪、细节、意图）在翻译过程中大量丢失。用户说"要恐怖一点"，AI 写成"dark scary atmosphere"——抽象词模型根本不认，出来的东西必然跑偏。

**新流程**（融合后）：

```
阶段 0（新增）：需求 → 提示词
  用户原始想法
    → prompt-optimizer 选模板优化（结构化、精确化、补全缺失信息）
    → 注入本工作流的生成铁律（P00 规范 + I2V 四段式）
    → 产出「ComfyUI 就绪提示词包」
阶段 1（原有）：ComfyUI 出图 / 出视频
阶段 2（原有）：质检 → 配音 → 合成 → 交付
```

**核心变化：提示词不再是"AI 现场编的"，而是"经引擎优化产出的"。** 用户的需求、想法、细节在阶段 0 被完整提取并固定成文本，后面 GPU 只负责执行。

## 二、阶段 0 详解：从想法到提示词

### 2.1 三种输入，三条路径

| 用户给什么 | 用哪个模板 | 产出什么 |
|---|---|---|
| **一句话/一段模糊想法**（"我要一个女司机夜班遇到怪乘客的镜头"） | `user-prompt-planning` 步骤化规划 | 拆成角色/目标/步骤/输出要求四段结构化提示词 |
| **有描述但太泛**（"恐怖的隧道镜头"） | `user-prompt-professional` 专业优化 | 精确画面描述：主体+动作+场景+光影+镜头，抽象词全部落地为可视元素 |
| **已有提示词要定向改**（"动作太快了，改慢点"） | `iterate` 通用迭代 | 保留原词结构与变量，只改指定方向 |
| **完整风格设定/系统提示词** | `general-optimize` 通用优化 | Role/Profile/Skills/Rules/Workflows 六段重组 |
| **要画新图**（"画个半夜的加油站"） | `image-general-optimize` 通用自然语言优化 | 3–6 句分层画面描述（静态定格，禁摄影术语） |
| **复杂生图需求/要结构化数据** | `image-json-structured-optimize` 中文 JSON 结构化 | 严格 JSON；「约束.避免」段直接拆进 negative 字段 |
| **图已生成要定向改**（"表情改成惊恐"） | `image2image-general-optimize` 通用编辑优化 | 先判 添加/删除/替换/增强 四意图，只改指定区域 |
| **多张参考图保一致**（锚点+差分+母版） | `multiimage-optimize` 多图关系整理 | 图1/图2/图3 引用，文字只写关系和变化 |
| **参考图复刻成模板** | `image-prompt-from-reference-image` 参考图复刻 | {prompt, defaults} JSON，变量位=量产控制位 |
| **版式母版换新主体量产** | `image-prompt-migration` 风格迁移 | 版式骨架保留，新主体置入槽位 |

### 2.2 铁律注入（关键步骤）

prompt-optimizer 产出通用提示词后，**必须过一遍本工作流的铁律检查**（源自 `00_通用工作链_不限于漫剧/02_提示词写法_通用.md` 与 `02_工作流程/04_视频I2V生成流程.md`；原 `07_提示词与剧本/P00_提示词规范与风格锚.md` 已随剧集清理删除，铁律条文已并入前两处）：

| # | 铁律 | 不过怎么办 |
|---|---|---|
| 1 | 不写否定式描述 | "不要有路灯"→"公路两侧没有任何光源，只有黑暗" |
| 2 | 不写抽象情绪 | "恐怖/温暖/高级"→具体画面元素（"她把手机往耳朵上贴紧一点，手在抖"） |
| 3 | 不写中文文字 | 需要文字的位置写"留白，无文字" |
| 4 | 一镜一意图 | 想表达两件事就拆成两镜 |
| 5 | 动作能在几秒内做完 | "走过整个画面"→"走到右三分之一处停住" |
| 6 | 挂参考图不写长相/服装/姓名 | 参考图已给的信息，文字再写就换脸 |
| 7 | I2V 帧数 4n+1 | 要 60 帧传 61，出片裁回 |
| 8 | I2V 结尾有终止态 | 动作提示词结尾必须有"停住/停下/不动了" |

**图片场景差异**：铁律 5 反过来用（静帧静态化，不写"正要…"）；铁律 7/8 不适用（无帧数无终止态）；额外加一条**禁摄影术语**（85mm/浅景深/体积光/电影级——本项目是 2D 高清手绘风，摄影词会把模型带向写实渲染）。

### 2.3 产出格式：ComfyUI 就绪提示词包

阶段 0 的最终产出不是一句提示词，是一个**小包**（可直接贴进 `SHOTS_EP04.json` 或 `IMAGES.json`）：

```json
{
  "shot_id": "EP04-S17",
  "positive": "夜，一名女子站在台阶上，把手机贴在耳边等着，身体几乎不动。她缓慢地低下头，把手机往耳朵上贴紧一点，停住。雨持续落在水泥台阶和铁皮雨棚上，远处有车驶过积水的声音。固定机位，中景。机位固定不动。",
  "negative": "多余手指，畸形手，肢体变形，脸部崩坏，双眼不对称，多余人物，文字乱码，水印，logo，过度磨皮，换脸，五官漂移",
  "frames": 61,
  "params": {"steps": 24, "cfg": 5.0, "shift": 8.0, "sampler": "euler"},
  "notes": "首帧挂 EX_LINYAN 表情差分；动作预算 2.5s；G5/G6 质检必过"
}
```

## 三、与原流程的接缝

阶段 0 产出**喂给**原九段流程的两处：

| 原环节 | 收什么 | 怎么用 |
|---|---|---|
| ⑥ 关键帧（生图） | `prompt` + `negative` + 尺寸/参数 | 进 `07_提示词与剧本/IMAGES.json`，跑 `09_工具脚本/一键生图.bat` |
| ⑦ 图生视频（I2V） | `positive`（四段式）+ `negative` + `frames` | 进 `06_分镜与时间轴/SHOTS_EP04.json`，跑 `09_工具脚本/一键生成EP04.bat` |

⚠️ **已知小坑**：`一键生图.bat` 里写死的旧路径 `源机器E盘灵异悬疑短剧_资产包\04_提示词` 已废弃（资产包已并入本项目），跑之前先确认 IMAGES.json 在本项目目录里，或手动改 bat 里的 `cd` 路径。

**质量门不变**：G1–G7 照旧。阶段 0 只是让喂进管线的提示词更准，不替代任何质检。

## 五、快速上手（三种用法）

### 用法 A：对话里直接让 AI 走融合流程（推荐）

对本机 WorkBuddy 说：

> 「用提示词工程流程，帮我把这个想法做成 EP04 风格的提示词包：<你的想法>」

AI 会：选模板 → 优化 → 过铁律 → 产出就绪提示词包。skill 已装（`~/.workbuddy/skills/prompt-optimizer/`），零配置。

### 用法 B：Web 应用里手动优化

双击 `prompt-optimizer技能包/03_Web应用/启动prompt-optimizer.cmd`，浏览器里图形化操作（API key 自理），优化完把结果喂给 ComfyUI。

### 用法 C：换机器/换人接手

`prompt-optimizer技能包/01_技能包/prompt-optimizer.zip` 是完整备份，解压即用。
