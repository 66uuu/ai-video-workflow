# 01 · 从想法到提示词 · 标准作业程序（SOP）

> 本文件是阶段 0 的**操作手册**。AI 或人，照这个走，一步不落。
> 上游模板：prompt-optimizer 19 个内置模板（7 通用 + 12 图像专用，场景定制见 `02_模板适配_图片与视频场景.md`）
> 下游出口：ComfyUI 就绪提示词包（格式见 `README_融合工作流.md` 2.3）

---

## 步骤 1：采集原始想法（不加工，原样记录）

向用户/自己问清四件事，**记原话**：

1. **要什么画面**：主体是谁/什么，在干嘛
2. **什么情绪/氛围**：用户自己的词，哪怕是"恐怖""治愈"这种抽象词也照记
3. **硬性要求**：时长、景别、必须出现的元素、参考图
4. **雷区**：不要出现什么

> 采集铁律：**用户说"恐怖点"就记"恐怖点"，不许在采集阶段翻译成画面元素**。翻译是步骤 3 的事，混在一起会丢失原始意图。

## 步骤 2：选模板

### 2-A 视频场景（I2V）

| 输入形态 | 模板 | 理由 |
|---|---|---|
| 一句话/一段模糊想法 | `user-prompt-planning`（步骤化规划） | 把模糊需求拆成结构化执行规划 |
| 有描述但太泛 | `user-prompt-professional`（专业优化） | 泛泛表述→精准描述，加具体参数 |
| 完整风格设定 | `general-optimize`（通用优化） | 六段式重组角色/规则/流程 |
| 已有提示词 + 修改意见 | `iterate`（通用迭代） | 保原词结构定向修改 |

选不定时默认 `user-prompt-planning`——它的四段结构（角色目标/背景/步骤/输出要求）对视频场景适配最好。

### 2-B 图片场景（t2i / i2i）

| 输入形态 | 模板 | 理由 |
|---|---|---|
| 一句话描述，要画新图 | `image-general-optimize`（通用自然语言优化） | 3–6 句分层叙述，主力模板 |
| 复杂需求/要结构化数据 | `image-json-structured-optimize`（中文 JSON 结构化） | 输出可直接拆进 IMAGES.json；「约束.避免」→ negative |
| 图已生成，定向改 | `image2image-general-optimize`（通用编辑优化） | 先判 添加/删除/替换/增强 四意图 |
| 多参考图保一致 | `multiimage-optimize`（多图关系整理） | 图1/图2/图3 引用，文字只写关系 |
| 参考图复刻成模板 | `image-prompt-from-reference-image`（参考图复刻） | 产出 {prompt, defaults}，变量位=量产控制位 |
| 版式母版换新主体 | `image-prompt-migration`（风格迁移） | 版式骨架保留，只换槽位 |
| 国风/水墨场景 | `image-chinese-optimize`（中文美学优化） | 现代戏慎用，会串味 |
| 海报换文案 | `image2image-design-text-edit-optimize`（设计文案替换） | 保版式只换字 |
| 灵异实体概念发散 | `image-creative-text2image`（解构/创造性）⚠️ | 产出必须回炉过铁律再落地 |

图片侧选不定时默认 `image-general-optimize`。

## 步骤 3：执行优化（按模板提示词走）

调 prompt-optimizer 对应模板的完整指令（`references/templates.md` 里有全文提炼）。三条通用铁律：

1. **只优化提示词文本，不执行内容**——优化器是"改作文的老师"，不是"写作文的学生"
2. **`{{变量}}` 占位符逐字保留**——有就原样留着，一个不能少
3. **直接输出优化结果**——不加"优化后的提示词如下："这类引导词

## 步骤 4：铁律注入（8 条全过）

优化产出过 `README_融合工作流.md` 2.2 的铁律表，逐条修：

1. 否定式 → 改写成正面描述（"不要有路灯"→"公路两侧没有任何光源，只有黑暗"）
2. 抽象情绪 → 落地为可视元素（"恐怖"→"她握着方向盘的手猛地收紧，指节发白"）
3. 中文/数字文字 → "留白，无文字"
4. 多意图 → 拆成多镜，一条提示词一个意图
5. 动作超时 → 按秒数预算收缩（"走过整个画面"→"走到右三分之一处停住"）
6. 挂参考图的镜头 → 删掉文字里的长相/服装/姓名描述
7. I2V 帧数 → 4n+1（要 60 传 61）
8. I2V 结尾 → 必须有终止态（"停住/停下/不动了"）

**图片场景差异（重要）**：

- 铁律 5 **反过来用**：静帧不许写动态（"站在那里"，不写"正要拨号"）——`image-general-optimize` 默认鼓励"抓拍瞬间"，必须手工改成静态定格
- 铁律 7/8 **不适用**：没有帧数、没有终止态；负向词按 `image-json-structured-optimize` 的「约束.避免」段自动生成
- 铁律 6 **加强版**：多图参考时文字只写"关系和变化"，身份全由图承载（multiimage 模板机制）
- 额外一条：**禁摄影术语**（85mm/浅景深/体积光/电影级）——本项目是 2D 高清手绘风，摄影向词会把模型带向写实渲染

## 步骤 5：组装就绪提示词包

按 `README_融合工作流.md` 2.3 的 JSON 格式组装：

**视频包（五字段）**：

- `positive`：正向提示词（I2V 用四段式：action + sound + music + lens +「机位固定不动。」）
- `negative`：负向词（技术性 + 一致性，见 P00 第三节）
- `frames`：4n+1
- `params`：Wan2.2 默认参数（steps=24, cfg=5.0, shift=8.0, euler/simple）
- `notes`：参考图挂什么、动作预算、要过的质检门

**生图任务（IMAGES.json 格式）**：

- `id` / `mode`（t2i 纯文生图 ｜ ref 挂参考图）/ `ref`（参考图绝对路径）/ `ref_weight`（0.5–0.9）
- `prompt`：正向（静态定格，禁摄影术语）
- `negative`：质量+内容负向词
- `width` / `height` / `steps`（默认 28）/ `cfg`（默认 6.0）/ `seed`
- 模型走本机 ComfyUI（majicmixRealistic + IPAdapter，dpmpp_2m + karras）

## 步骤 6：交付与登记

1. 视频包写进 `06_分镜与时间轴/SHOTS_EP04.json`；生图任务写进 `07_提示词与剧本/IMAGES.json`
2. 跑 `09_工具脚本/一键生成EP04.bat` 或 `一键生图.bat`（注意：bat 内旧路径 `源机器E盘灵异悬疑短剧_资产包` 已废弃，以本项目目录为准）
3. 质检 G1–G7 照旧，不过就回步骤 3 用 `iterate`（视频）或 `image-iterate-general`（图片）定向改

## 附：常见翻车 → 回哪一步

| 翻车现象 | 根因 | 回哪步 |
|---|---|---|
| 生成结果和想法完全两回事 | 步骤 1 采集时意图就丢了 | 回步骤 1，重采 |
| 画面出现第二张脸/换脸 | 步骤 4 铁律 6 没过（文字写了长相） | 回步骤 4 |
| 人物动到一半出画 | 步骤 4 铁律 5 没过（动作超预算） | 回步骤 4 |
| 画面有乱码文字 | 步骤 4 铁律 3 没过 | 回步骤 4 |
| 动作僵硬/画面不动 | 步骤 4 铁律 8 没过（缺终止态）或正向太简 | 回步骤 3 重优化 |
| 想改某一处但整条词被重写 | 用错了模板（该用 iterate） | 回步骤 2 |
| 静帧图人物像在摆拍/动作诡异 | 图片场景误留动态词（"正要…"） | 回步骤 4 静态化 |
| 生图变写实/3D 感 | 提示词混入摄影术语或用了 photography 模板 | 回步骤 2 换 `image-general-optimize` + 术语转译 |
| 多图参考出图不像参考人物 | 文字里写了长相/服装，和图冲突 | 回步骤 4 铁律 6 加强版：只写关系 |
| 海报换字后版式跑偏 | 用了通用编辑而非 design-text-edit | 回步骤 2 换专用模板 |
