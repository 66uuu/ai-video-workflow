## 一、三十秒上手

前提：机器上已经装好 ComfyUI 且服务在跑。没装的话先看 `02_下载与安装_从零到能出图.md`。

```bat
cd 11_本地工具接入指南\bridge

:: 一条命令检查这台机器能不能直接开工
python selfcheck.py
```

看到 `✔ 环境就绪，可以直接开工` 就成了。

然后：

```bat
:: 出一张图
python nr_bridge.py t2i --prompt "1girl, portrait, photorealistic, natural light" --out .

:: 用刚出的图出一段视频
python nr_bridge.py i2v --image NR_T2I_00001_.png --prompt "夜，她缓慢抬头，停住。雨声。无配乐。近景，50mm。" --frames 72 --out .
```

**这就是全部的"AI 连接本地工具"。** 没有别的步骤。

## 三、`bridge` 是什么

一句话：**把"打 ComfyUI 的 HTTP API"包装成几个函数。**

| 你想要的 | 一行代码 |
|---|---|
| 检查服务活不活 | `Comfy().health()` |
| 出一张图 | `c.run(build_t2i(prompt), "out/")` |
| 挂参考图保人物一致 | `wf = build_t2i_ref(prompt, uploaded, ref_weight=0.5)` |
| 出一段视频 | `c.run(build_i2v(uploaded, prompt, frames=72), "out/")` |
| 上传首帧 | `c.upload_image("本地图.png")` |
| 查节点全不全 | `c.has_nodes([...])` |

**零第三方依赖**（只用 Python 标准库）。这意味着：
- 不用 `pip install` 任何东西
- 用 ComfyUI 的 python、系统的 python、随便哪个 python 都行

### 为什么不用现成的库

现成的 ComfyUI 客户端库通常要求特定的 python 环境，而且会把"路径探测""绕代理""4n+1 换算"这些本项目的关键细节丢掉。自己写 400 行更可控。

## 四、链路长什么样

```
你的需求（要一张图 / 一段视频）
      ↓
AI 写提示词 + 指定参考图 + 帧数
      ↓
nr_bridge.build_t2i() / build_i2v()      ← 翻译成 ComfyUI 的工作流 JSON
      ↓
POST /prompt  →  ComfyUI 内存队列
      ↓
ComfyUI 自己算（你的显卡，不耗任何额度）
      ↓
GET /history 轮询 → GET /view 下载
      ↓
落地到本地目录
```

**关键**：`POST /prompt` 之后，**脚本断开也不影响**。任务在 ComfyUI 的队列里，它自己跑完。

这就是为什么可以"压完队列就关电脑桌面"，第二天再收片。

## 五、这套东西解决了什么

| 原来 | 现在 |
|---|---|
| 每次生成都消耗外部额度 | **电费**。31 镜一集约 0.25 度 |
| 要开网页、点按钮、填表 | 一行代码 / 双击 bat |
| 批量和断点续跑要人盯着 | 压队列后自动跑，崩了能续 |
| 换电脑就得重新摸索 | `selfcheck.py` 告诉你缺什么 |
| 人物一致性靠运气 | 参考图 + IPAdapter 权重分级，可复现 |

## 六、这套东西不解决什么（诚实说明）

| 做不到 | 原因 | 怎么办 |
|---|---|---|
| 出中文文字 | AI 画中文必是乱码 | 留白 + 后期人工贴字 |
| 出声 | Wan2.2 是无声模型 | 台词走 TTS 后期 |
| 单段超 5 秒 | 121 帧是模型上限 | 拆镜，靠剪辑节奏补 |
| 精确道具交互 | SD1.5 服从度差 | 改导演方案，不硬要 |
| 风格与商业模型完全一致 | 底座不同源，调不平 | 二选一：接受本地风格 / 关键帧走云端 |
| 6GB 以下显存跑 121 帧 | 显存不够 | 降帧数、降分辨率、降精度 |

**最后一条尤其重要**：本地生成是 3D 半写实，已经锁定的资产是厚涂剧漫。这个差异不是参数问题，是底座模型走了不同路子。详见 `../01_全流程工作报告/P25_本地全链路跑通报告.md` 第三节。

## 七、三条最常见的错误

**1. 忘了绕代理**

```bat
curl --noproxy "*" http://127.0.0.1:8188/queue     ← 这个参数不能省
```

不绕代理会报 `upstream connect failed` / `10061`，**极容易被误判成"服务没起来"**。服务其实好好跑着。

`nr_bridge` 内部已经强制绕代理，不受影响。

**2. 装完插件没重启 ComfyUI**

节点列表是服务启动时扫的。装完插件不重启，`selfcheck.py` 就会报"缺 UnetLoaderGGUF"。

看到缺节点，第一反应是"重启了吗"，不是"没装上"。

**3. 帧数没做 4n+1**

Wan 要求 `length = 4n+1`。目标 72 帧要传 73，出片后裁回 72。

`build_i2v()` 自动做了（打印"目标 72 帧 → 生成 73 帧"就是它在工作）。手写工作流时要自己处理。

## 八、和 `09_工具脚本` 什么关系

| | `09_工具脚本` | `11_本地工具接入指南/bridge` |
|---|---|---|
| 定位 | **业务脚本**（EP04 专用） | **通用接入层** |
| 内容 | `batch_local.py`（读镜表和提示词，跑整集） | `nr_bridge.py`（只管连和生成） |

**建议**：以后写新脚本，`from nr_bridge import Comfy, build_i2v`，不要再硬编码路径。
