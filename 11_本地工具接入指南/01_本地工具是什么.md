# 01 · 本地工具是什么（ComfyUI）

> 如果你只想知道"这东西为什么能让我不花额度生成图片和视频"，看这一篇就够了。

---

## 一、一句话

**ComfyUI 是一个跑在你自己电脑上的 AI 生成引擎，它对外暴露一个 HTTP 服务（默认 `127.0.0.1:8188`）。**
因为它是个服务，所以**程序可以直接调用它**——这就是"AI 连接本地工具自动化生成"的全部原理。

不是黑魔法，就是一个本地 API。

---

## 二、它和"网页生图"有什么不同

| | 网页版（Midjourney / 即梦 / 各种云） | ComfyUI（本地） |
|---|---|---|
| 算力在哪 | 别人的服务器 | **你的显卡** |
| 花钱吗 | 按次/按额度 | **电费** |
| 需要联网吗 | 必须 | **不用**（装好之后） |
| 能改流程吗 | 只能填提示词 | **每个环节都能改** |
| 能不能被程序调 | 要申请 API key，有的没开放 | **直接 HTTP，零门槛** |
| 一致性控制 | 弱（靠 seed） | **强**（IPAdapter / ControlNet / 参考图） |
| 速度 | 看服务器排队 | 看你的卡 |

**关键差异是最后两条**：可控性和可编程性。

做短剧最要命的是"三十个镜头里女主角是同一张脸"。网页版做不到，本地可以（挂参考图 + IPAdapter，权重调到 0.5）。

---

## 三、它长什么样

```
ComfyUI
├── 服务端        一个 Python 进程，监听 8188 端口
├── 前端          浏览器打开的节点编辑器（拖拽连线）
├── models/       放模型文件的地方（本剧用了 13.1GB）
├── input/        放待处理素材（我们要上传的首帧图放这）
├── output/       生成结果落这，再通过 API 取走
└── custom_nodes/ 插件目录
```

**重要**：那个浏览器界面是**给人用的**。我们要做自动化，根本不碰界面，直接打 API。

界面在这里的唯一用处是：出问题时可以手动跑一遍，确认是代码错了还是模型错了。

---

## 四、核心概念（六个，够用了）

### 1. 节点图（Workflow）

一条生成流程 = 一张有向图。每个节点干一件事，节点之间用线连起来传数据。

生图的最小图（8 个节点）：

```
CheckpointLoader  →  CLIPTextEncode（正向）
                  →  CLIPTextEncode（负向）
                  →  EmptyLatentImage
                            ↓
                        KSampler
                            ↓
                        VAEDecode
                            ↓
                        SaveImage
```

出视频的图（我们实际在用的 12 个节点）：

```
UnetLoaderGGUF → ModelSamplingSD3
CLIPLoaderGGUF → CLIPTextEncode ×2
LoadImage（首帧）+ VAELoader → Wan22ImageToVideoLatent
                                    ↓
                                KSampler
                                    ↓
                                VAEDecode
                                    ↓
                    CreateVideo → SaveVideo
```

### 2. 模型（Checkpoint / UNet）

就是"会画画的脑子"。不同模型画风完全不同。

本剧用两个：
- `majicmixRealistic_v7`（SD1.5，2.0GB）—— 生图
- `Wan2.2-TI2V-5B`（3.6GB，GGUF 量化）—— 图生视频

### 3. VAE

**负责"翻译"**：在"人能看的图"和"模型能算的潜空间"之间来回转。

- 编码：图 → latent
- 解码：latent → 图

Wan2.2 的 VAE 压缩比是 **16×16×4**（空间 16 倍，时间 4 倍）。这就是为什么 512×768 的视频在 8GB 卡上能跑——latent 只有 32×48×31。

### 4. Latent（潜空间）

模型不直接算像素，算的是压缩后的"潜表示"。latent 尺寸决定显存占用。

### 5. 采样器（KSampler）

把"噪声"一步步变成"图"的过程。

| 参数 | 本剧取值 | 作用 |
|---|---|---|
| steps | 24（视频）/ 28（图） | 迭代次数，越多越细也越慢 |
| cfg | 5.0（视频）/ 7.0（图） | 多听提示词的话。太高会僵 |
| sampler | euler（视频）/ dpmpp_2m（图） | 采样算法 |
| scheduler | simple / karras | 噪声调度 |
| seed | 固定 | 固定了才能复现 |

### 6. 节点连线的语法（这个必须懂）

API 里节点之间不是"连线对象"，是一个二元数组：

```json
"model": ["4", 0]
```

意思是：**取第 4 号节点的第 0 个输出**。

```json
{
  "4": { "class_type": "CheckpointLoaderSimple", "inputs": { "ckpt_name": "xxx.safetensors" } },
  "3": { "class_type": "KSampler", "inputs": { "model": ["4", 0], ... } }
}
```

`KSampler` 的 `model` 输入 = 4 号节点的第 0 号输出（MODEL）。

这就是全部语法。**没有别的。**

## 五、为什么要用 GGUF 版本

Wan2.2 TI2V-5B 原始是 fp16（约 10GB），8GB 卡装不下。

GGUF 是量化格式：
- `Q5_K_M` → 3.6GB，画质损失很小
- `Q4_K_M` → 更小，画质掉一档
- `Q8` → 接近原始，但 8GB 卡跑不动

我们选 `Q5_K_M` —— 显存（6.4–7.3GB 峰值）和画质的平衡点。

**代价**：需要额外装 `ComfyUI-GGUF` 插件才能加载。

## 六、它能做什么 / 不能做什么（本机实测）

### 能

| 任务 | 实测 |
|---|---|
| SD1.5 文生图 512×768 | 8 秒/张 |
| 挂参考图保人物一致 | ✅ IPAdapter 权重 0.5 有效 |
| Wan2.2 图生视频 72 帧 | 286 秒 |
| Wan2.2 图生视频 121 帧 | 572 秒，显存峰值 7.3GB 不炸 |
| 批量排队跑整集 | ✅ 31 镜约 2.6 小时 |

### 不能

| 不能 | 原因 |
|---|---|
| 出中文文字 | AI 画中文必是乱码，必须后期贴 |
| 出声 | Wan2.2 是无声模型，台词走 TTS |
| 精确道具交互 | 要"双手拿着照片"，两轮都画不出来 |
| 单段超 5 秒 | 121 帧是上限 |
| 稳定出"同一个人" | 除非挂参考图，否则每次都是新脸 |
| 跑 SDXL 三件套 | 8.5GB，必炸 |

## 七、为什么"AI 能连它"

因为它的设计从第一天就是**前后端分离**的：

```
浏览器界面  ──HTTP──→  8188 服务端  ──→  显卡
你的脚本    ──HTTP──→       ↑
```

浏览器和你的脚本，在这个服务眼里**没有区别**——都是发 JSON 过来、收 JSON 回去的客户端。

所以：

> **AI 不需要"操作界面"。AI 直接发 HTTP 请求。**

这就是我们要做的事的全部。具体协议见 `03_AI如何连接_通信协议.md`。

---

## 八、和"AI 操作浏览器"的区别

有人会想：能不能让 AI 去点那个网页界面？

能，但**极不推荐**：

| 方式 | 稳定性 | 速度 | 换机可移植 |
|---|---|---|---|
| 点界面（浏览器自动化） | 低（界面一改就废） | 慢（每步要等渲染） | 差 |
| **打 API** | 高（协议稳定） | 快（一个请求） | **好（只改地址）** |

而且点界面时，AI 还得"看"截图判断状态，费 token 又不可靠。

**打 API 是这个场景唯一正确的做法。** 本包里的全部脚本都是打 API。
