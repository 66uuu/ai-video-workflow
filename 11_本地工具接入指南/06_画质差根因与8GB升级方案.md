# 画质差的根因诊断 + 8GB 显存可落地的升级方案

> 适用机器：RTX 4060 Laptop GPU，**总显存 8GB**（实测当前占用 3.5GB / 剩 4.4GB）
> 当前 ComfyUI：在线（127.0.0.1:8188，HTTP 200）
> 写于：2026-10-18

---

## 0. 一句话结论

- **出图差不是 ComfyUI 的锅，也不是提示词的锅，是你的底模代际太老。**
  本机两个出图 checkpoints（majicmixRealistic_v7、Counterfeit-V2.5）**全部是 SD1.5 底模**。SD1.5 原生分辨率 512×768，这是 U-Net 架构的硬天花板，任何提示词工程都救不了。
- **出视频差是体量决定的。** 你跑的是 `Wan2.2-TI2V-5B-Q5_K_M`（5B 小模型 + 量化），它"参考"首帧而非"锁定"首帧，逐帧漂移（脸变、身材变）是这种体量 inherent 的。
- **8GB 上画质提升性价比最高的单一动作：把出图模型从 SD1.5 换成 FLUX.1-schnell GGUF（Q4_K_S / Q5_K_S）。** 这是从 U-Net 到 DiT 的架构代际跨越，脸/手/解剖质量碾压 SD1.5，且 schnell 仅 4 步、量化后 8GB 能跑。
- **视频在 8GB 上没有"又小又好"的本地替代。** 更好的视频模型（Wan2.2 14B、HunyuanVideo 1.5、LTX-2）都要 12–24GB。8GB 的现实选择是：接受 5B + 调参，或换卡 / 上云。

## 1. 根因详解

### 1.1 出图：SD1.5 的天花板（已实测确认）

| 本机模型 | 类型 | 大小 | 原生分辨率 |
|---|---|---|---|
| majicmixRealistic_v7.safetensors | **SD1.5** 微调 | 2.1GB | 512×768 |
| Counterfeit-V2.5_pruned.safetensors | **SD1.5** 微调 | 4.3GB | 512×768 |

- SD1.5 的训练分辨率就是 512²。一旦长边超过 ~768，脸部结构、四肢比例、手指数量就会崩。
- 你之前用 512×768 + 一堆反向词（split screen / grey suit / furniture 等）去"救"，本质上是在和架构极限搏斗——再多提示词也只是掩盖，无法根治。
- **结论：换底模是唯一出路，不是调参。**

### 1.2 出视频：5B 小模型"参考"而非"锁定"

- Wan2.2 官方有两档：**5B**（消费级）和 **14B**（旗舰）。你的是 5B，且已被量化到 Q5_K_M 才能在 8GB 上跑。
- 5B 的参数容量有限，学不会"严格保持首帧身份 + 姿态 + 构图"，所以人物在视频里会缓慢漂移。量化（Q5_K_M）进一步损失高频细节。
- 这是体量决定的，不是采样步数或提示词能根除的。

## 2. 出图替代方案（按 8GB 可行性排序）

| 模型 | 架构 / 参数 | 8GB 可行性 | 画质 | 关键备注 |
|---|---|---|---|---|
| 现状 SD1.5 | U-Net / 0.9B / 512 | ✅ 流畅 | ★★ | 架构天花板 |
| SDXL | U-Net / 3.5B / 1024 | ⚠️ 需 `--lowvram` + Tiled VAE，慢 2–3 倍 | ★★★★ | 生态最厚、LoRA 最多 |
| SD3.5 Medium | DiT / 2.5B / ~1MP | ✅ 比 SDXL 省显存 | ★★★★ | 官方权重仅非商用 |
| **FLUX.1-schnell GGUF** | DiT / 12B 量化 / ~1MP | ✅ Q4_K_S≈6–7GB，4 步极快 | ★★★★★ | **8GB 首选** |
| FLUX.1-dev GGUF | DiT / 12B 量化 | ⚠️ 需 T5-XXL GGUF，较慢 | ★★★★★+ | 质量更高但慢 |

### 推荐：FLUX.1-schnell GGUF（Q4_K_S 或 Q5_K_S）

- **为什么是它**：FLUX 是 2024–2026 的画质标杆，采用 DiT 架构（不是 SD 的 U-Net），原生约 1MP，对人脸、手部、解剖结构的还原远超 SD1.5。schnell 是 4 步蒸馏版（Apache 2.0，可商用），量化到 GGUF 后 8GB 能跑且出图快。
- **需要补的东西**（都是 ComfyUI 插件 / 文件，不难）：
  1. `ComfyUI-GGUF` 自定义节点（city96 出品）—— 负责加载 `.gguf` 大模型。
  2. FLUX.1-schnell GGUF 主模型文件（Q4_K_S 约 6–7GB 起，Q5_K_S 更大）。
  3. T5-XXL 编码器 GGUF（city96 同样提供）—— FLUX 的 text encoder，必须量化版否则爆显存。
  4. FLUX 专属工作流：双 CLIPLoader（clip_l + t5xxl）+ UNETLoader(GGUF) + 采样器（步数 4，scheduler 用 simple / beta）。
- **保脸流程可平移**：你现有的 IPAdapter 保脸管线可以接到 FLUX 上（FLUX 也有对应的 IPAdapter 节点），角色一致性不会丢。

### 备选：SDXL

- 如果你更看重"生态厚、LoRA 多、教程多"，SDXL 是稳妥升级（1024 原生，像素是 SD1.5 的 4 倍）。
- 8GB 上必须 `--lowvram --force-fp16` + Tiled VAE（tile_size 512），速度比 SD1.5 慢 2–3 倍，但画质明显提升。
- 缺点：仍不如 FLUX 的脸/手质量。

## 3. 出视频的现实选择（8GB）

**坦诚结论：8GB 上没有"质量飞跃且能本地跑"的视频模型。** 当前开源视频模型的最低门槛：

| 模型 | 最低显存 | 8GB 能否跑 |
|---|---|---|
| Wan2.2-TI2V-5B（现状） | ~6–8GB（量化） | ✅ 但小模型漂移 |
| Wan2.2 14B | 24GB+ | ❌ |
| HunyuanVideo 1.5 | 14GB+ | ❌（offload 也极慢） |
| LTX-2 | ~12GB+ | ❌（ComfyUI 已官方支持节点，但 8GB 吃紧） |

### 不换模型也能做的"压漂移"改进

1. **提步数**：I2V 步数从 20 提到 28–30，采样器换成 `res_multistep` 或 `uni_pc`（比默认更稳）。
2. **首帧锁定增强**：在原生首帧参考之外，叠加首帧 ControlNet（如 Wan 生态的 LightX2V / 首帧参考控制），强制约束身份不漂。
3. **分辨率/帧数取舍**：480p × 81 帧比 720p × 81 帧稳定得多；帧数越少漂移累积越少。
4. **后处理**：用你已有的 `drift_check.py` 逐段检测漂移，漂移严重的片段用首帧重生成或局部重绘。

### 真要质量飞跃，只有两条路

- **换卡**：RTX 4070 12G（约 ¥4000）或 RTX 3090 24G（二手约 ¥6000–8000）→ 直接上 Wan2.2 14B / HunyuanVideo 1.5。
- **上云 GPU**：偶发重型视频任务用云（按小时计费），本地只跑出图 + 轻量视频。
