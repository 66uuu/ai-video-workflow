# 06 · 合成与交付流程

> 这一段的原则：**只做交付，不改内容。**
> 生成的原片原封不动一并打包，出了问题能倒查是哪一步错的。

---

## 一、四步流程

```
① 收片      从 ComfyUI 队列取回 <镜号>_i2v.mp4
② 统一规格  逐镜转 1024×1536 / 24fps / yuv420p / 补齐静音轨
③ 拼接      按时间轴顺序 concat
④ 打包      正片 + 逐镜原片 + 时间轴 + 提示词 + 交付说明 → 桌面
```

---

## 二、逐镜统一规格（这一步不能省）

模型出的是 512×768。成片要 1024×1536。中间必须做一次规范化，否则拼接时会出现：

- 分辨率不一致 → concat 直接失败
- 帧率不一致 → 音画不同步、播放器卡顿
- 像素格式不一致（yuv444 vs yuv420）→ 手机上放不出来
- 部分镜有音轨部分没有 → 剪辑软件报错

### 规范化命令

```bat
ffmpeg -y -i raw.mp4 ^
  -f lavfi -i anullsrc=r=48000:cl=stereo ^
  -vf scale=1024:1536:flags=lanczos ^
  -c:v libx264 -preset medium -crf 17 ^
  -pix_fmt yuv420p -r 24 ^
  -c:a aac -b:a 128k ^
  -shortest -movflags +faststart ^
  out.mp4 -loglevel error
```

### 参数逐条解释

| 参数 | 为什么 |
|---|---|
| `-f lavfi -i anullsrc=r=48000:cl=stereo` | **补一条静音轨**。没有音轨的 mp4 在部分播放器/剪辑软件里会报错。48kHz 立体声是标准 |
| `scale=1024:1536:flags=lanczos` | 2× 放大。**lanczos 是锐度保持最好的插值**，比 bicubic 好一档 |
| `-crf 17` | 接近视觉无损。成片要再压一次时才有余量，crf 20 二次压缩会有明显块 |
| `-preset medium` | slow 太慢（31 镜要多等半小时），fast 画质掉。medium 是平衡点 |
| `-pix_fmt yuv420p` | **手机/网页播放的唯一安全格式**。YUV444 在浏览器里播不出来 |
| `-r 24` | 强制统一帧率。哪怕源是 24.0001 也要对齐 |
| `-shortest` | 音轨和视频轨取短的，避免尾部黑屏 |
| `+faststart` | moov 原子前置，**网页上传/预览能边下边播** |

## 三、拼接

用 concat demuxer，不用 filter_complex。

```
file 'normalized/01_S01.mp4'
file 'normalized/02_S02.mp4'
...
```

```bat
ffmpeg -y -f concat -safe 0 -i EP04_concat.txt -c copy -movflags +faststart 正片.mp4
```

**用 `-c copy` 不重新编码。** 因为每一镜已经统一过规格了，重编只会损失画质、浪费时间。

**前提**：所有镜头的编码参数必须完全一致。这就是第二步存在的意义。

## 四、缺镜头怎么办

`assemble_ep04.py` 的默认行为：**缺镜头拒绝出正片**，只出预览。

```bat
python assemble_ep04.py                  :: 缺镜头 → 只出预览，不出正片
python assemble_ep04.py --allow-partial  :: 缺镜头也拼（中途看效果用）
python assemble_ep04.py --native         :: 不放大，保持 512×768
```

**为什么默认拒绝**：缺镜的正片如果被当成成品发出去，就再也说不清"这版缺了哪几镜"。宁可不出。

中途看效果用 `--allow-partial`，但**输出文件名必须带"预览"**——EP04 当前那个 `夜路司机别回头_EP04_预览_20261018.mp4` 就是这么来的。

## 五、打包结构

```
桌面\夜路司机_EP04_交付_<日期>\
├─ 夜路司机别回头_EP04_<时长>s.mp4      正片
├─ 分镜原片\                            模型原始输出，未二次处理
│   ├─ 01_S01.mp4
│   ├─ 02_S02.mp4
│   └─ ...
├─ EP04_timeline_v2.csv / .json         时间轴
├─ SHOTS_EP04.json                      提示词与参数
├─ EP04_提示词包.md                      给人读的提示词汇总
└─ 交付说明.md                           这一版是什么、缺什么、下一步
```

**"分镜原片"必须独立一份。** 因为一旦规范化+拼接，就无法回头判断"某镜糊是模型问题还是放大问题"。原片是唯一的证据链。

## 六、质量门 G7

```python
# 每镜时长与时间轴差 ≤ 1 帧
for shot in shots:
    actual = ffprobe_frames(normalized[shot.id])
    expected = shot.frames
    assert abs(actual - expected) <= 1, "帧数不符"
```

差超过 1 帧说明生成或裁切出了问题。常见原因：

| 现象 | 原因 |
|---|---|
| 少了 3–4 帧 | 忘了 `4n+1` 裁切，或裁切时用了 `-t` 而不是 `-frames:v` |
| 多了几帧 | 生成时传了 121 但目标是 72，`-frames:v` 没生效 |
| 时长对但内容错 | 收错了镜（同秒生成、文件名撞了） |

## 十、进剪映精修（可选终段）

ffmpeg 出片是"一条直线"，出来就是成片。如果想在专业剪辑软件里再修一遍
（调色、转场、特效、贴纸、换 BGM），可以让工作流**顺带生成一份剪映草稿**。

```bat
python ..\09_工具脚本\gen_jianying_draft.py ^
  --timeline "06_分镜与时间轴\EP04_timeline_v2.json" ^
  --video-dir "video_i2v" ^
  --audio "_产出\配音_EP04\voice_track.wav" ^
  --srt "_产出\配音_EP04\voice_track.srt" ^
  --bgm "BGM.mp3"
```

生成的草稿会出现在剪映草稿列表里，打开就是排好的四轨：

| 轨 | 内容 |
|---|---|
| 视频主轨 | 各镜 i2v 原片，按时间轴顺序 |
| 字幕轨 | SRT，或 timeline 里的 `dialogue` |
| 配音轨 | 整集配音 |
| BGM 轨 | 背景音乐（音量 0.3） |

**和 ffmpeg 出片的关系**：并行，不是替代。

- 要快、稳、可批量 → 用 `assemble_ep04.py` + `一键全链路出片.bat`（现状）
- 要人工再修一遍、加专业效果 → 用剪映草稿

**限制（本机剪映 11.7）**：

- 剪映 7+ 不支持脚本自动导出，草稿生成后需在剪映里手动点导出
- 只新建草稿，不改写已有草稿（剪映 6+ 的 `draft_content.json` 加密）
- 素材为本地绝对路径引用，别移动素材

依赖：`python -m pip install pyJianYingDraft`（系统 Python，非 ComfyUI venv）。
