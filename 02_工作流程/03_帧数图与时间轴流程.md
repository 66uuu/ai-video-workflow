# 03 · 帧数图与时间轴流程

> "帧数图"不是一张图，是一张**表**：每一镜从第几帧到第几帧、多长、这段里发生什么。
> 它是剧本和视频之间唯一的翻译层。这张表错了，后面每一步都错，而且错得很贵。

---

## 一、为什么必须精确到帧

因为有三件事只能靠帧数对齐：

1. **I2V 必须知道要生成多少帧** —— 生成多了少了，拼接时都会抖
2. **配音必须知道每句台词落在哪几帧** —— 台词和口型不同步，观众立刻出戏
3. **音效必须在正确的帧上归零** —— "抽空"错半秒就变成"卡带"

秒级精度不够。24fps 下一帧是 41.7 毫秒，人对画面跳变的感知阈值大约是 2 帧。所以时间轴的基本单位必须是**帧**，不是秒。

---

## 二、基础参数（全剧统一，不许改）

| 项 | 值 |
|---|---|
| 帧率 | **24 fps** |
| 分辨率 | 1024×1536（竖屏 2:3） |
| 生成分辨率 | 512×768（同样 2:3，出片后 2× 放大） |
| 编码 | H.264 / yuv420p / crf 17–18 |
| 音轨 | AAC 128k / 48kHz 立体声 |

**为什么生成用 512×768 而不用 1024×1536**：
Wan2.2 TI2V-5B 用 16×16×4 的高压缩 VAE，512×768 的 latent 只有 32×48×31，8GB 显存能跑到 121 帧。如果直接生成 1024×1536，显存必爆。
2:3 比例保持一致，2× lanczos 放大后画质损失可接受——因为竖屏短剧在手机上看，实际显示宽度不到 1080。

```json
    }

```

### 字段说明（哪些是机器读的，哪些是给人看的）

| 字段 | 谁用 | 说明 |
|---|---|---|
| `frames` | **机器** | 这镜要多少帧，`= duration × fps`，必须整数 |
| `start` / `end` | 机器 | 秒，决定 concat 顺序 |
| `total_frames` | **机器** | 校验用，必须 `== sum(frames)` |
| `shot_id` | 机器 | 与 `SHOTS_EP04.json` 对应，缺一不可 |
| `video_file` | 机器 | 补零命名（`01_S01.mp4`），`dir /b` 才不会乱序 |
| `beat` | 人 | 六段节拍归属，检查韵律用 |
| `shot_size` / `camera_move` | 人 | 导演意图，写提示词时参考 |
| `assets` | 人 | 这镜要用哪些资产，缺资产时一眼看出来 |
| `dialogue` / `speaker` | 人 | 台词与说话人，配音单的源 |
| `audio_note` | 人 | 这镜的声景要点 |
| `voids` | 人 | 抽空点，单独列出便于混音时找 |

## 四、`4n+1` 铁律（最容易翻车的一条）

**Wan2.2 要求帧数满足 `length = 4n + 1`。**

原因：VAE 的时间维压缩比是 4，latent 帧数必须是整数。传 60 帧进去，模型内部会取整，出来可能是 57 或 61 帧——**差这几帧，拼接时就是一次卡顿**。

做法：**生成用 `gen_len()` 上取整到 4n+1，出片后裁回精确帧数。**

```python
def gen_len(frames):
    """把目标帧数上取到最近的 4n+1"""
    return ((frames - 1 + 3) // 4) * 4 + 1
```

| 目标帧数 | 生成帧数 | 出片后裁到 |
|---|---|---|
| 60（2.5s） | 61 | 60 |
| 72（3.0s） | 73 | 72 |
| 84（3.5s） | 85 | 84 |
| 96（4.0s） | 97 | 96 |
| 120（5.0s） | 121 | 120 |

裁切用 ffmpeg：

```bat
ffmpeg -y -i raw.mp4 -frames:v 60 -c:v libx264 -crf 17 -pix_fmt yuv420p out.mp4
```

**`batch_local.py` 已经自动做了这件事。** 但如果你手动改帧数，别忘。

## 五、时间轴怎么生成

### 5.1 从分镜脚本生成

本剧用 `02_分镜/_tools/gen_ep04_timeline.py`。它做三件事：

1. 读基础镜表（24 镜）
2. 按 `_AFTER` / `_BEFORE` 字典把补拍镜插入正确位置
3. 输出 CSV + JSON，并校验总帧数

```python
# 补拍镜插入位置（示例）
_AFTER = {
    "S20": ["S20A"],   # 在 S20 之后插 S20A
    "S22": ["S22A", "S22B"],
}
_BEFORE = {
    "S24": ["S23A"],
}
```

**为什么要单独搞"补拍镜"这一层**：
第一版时间轴 73.0s，比目标 91s 少了 17.0s（反转段缺 10.5s、新钩子段缺 7.5s）。不是硬拉长每一镜，而是**在正确的节拍位置插入新镜头**。硬拉长会让节奏垮掉。

### 5.2 手工调整的规则

| 想做的事 | 正确做法 | 错误做法 |
|---|---|---|
| 某段太短 | 在该段**插入新镜** | 把已有的 2s 镜拉成 4s |
| 某镜动作做不完 | **缩短动作**或**拆成两镜** | 把这镜拉长（I2V 单次上限 5s） |
| 总时长不够 | 补"空镜/环境镜"给呼吸 | 每镜都加 0.3s |
| 总时长超了 | 砍掉信息重复的镜 | 全局加速（音效对不上） |

## 六、三重校验（每次改时间轴都跑）

```python
# 校验一：帧数守恒
assert sum(s["frames"] for s in shots) == total_frames

# 校验二：时间连续无空隙
prev = 0.0
for s in shots:
    assert abs(s["start"] - prev) < 1e-6, "有空隙或重叠"
    assert abs(s["end"] - s["start"] - s["frames"] / fps) < 1e-6, "帧数与时长相符"
    prev = s["end"]

# 校验三：节拍归位
# 六段：3 / 9 / 23 / 20 / 20 / 15 = 90s
```

EP04 v2 的实测结果：

```
总时长 91.000s ｜ 总帧数 2184 ｜ 31 镜
六段分布：3.0 / 9.0 / 23.0 / 20.5 / 20.5 / 15.0
校验：✔ 帧数守恒  ✔ 无空隙  ✔ 节拍归位
```

## 七、"抽空"要在时间轴上标出来

**抽空 = 全环境音归零到 −∞**，不是渐弱。

这两个必须分清：
- **抽空**：声音**没了**。0.5–0.8 秒的绝对静默。
- **渐弱**：声音**慢慢变小**。是过渡，不是事件。

本剧 EP04 有两个抽空点，写在 `voids` 里：

| 镜 | 偏移 | 时长 | 为什么这里 |
|---|---|---|---|
| S19 | 0.6s | 0.8s | 她看到死亡时间的瞬间 |
| S22 | 0.5s | 0.8s | 认知崩塌 |

**抽空不可复用不说明。** 五种用法必须每次写清"这次为什么用它"：
- 惊吓后没释放（物理）
- 开口前的静默（预警）
- 一句话落地后的空（信息冲击）
- 期待之后的空
- 认知崩塌

## 八、CSV 版本（给人看的）

JSON 给机器读，CSV 给人读。同一个脚本同时输出两份。

CSV 用 Excel 直接打开，可以排序、筛选、算占比。EP04 的 CSV 有 31 行，一眼能看出：
- 哪些镜有台词（`dialogue` 非空）
- 对白总时长占比（EP04 是 57%）
- 哪些镜缺资产（`assets` 里有 `CH_ARCHIVIST` 的就是没资产的）

**每次改完时间轴，先看 CSV 再跑生成。** 看 JSON 容易漏。

## 九、时长预算的常识

竖屏短剧一集 90–95 秒是黄金长度。拆到 24–32 镜：

| 镜别 | 典型时长 | 帧数 |
|---|---|---|
| 大特写（道具/眼睛） | 1.5–2.5s | 36–60 |
| 特写（脸） | 2.0–3.0s | 48–72 |
| 中景（半身） | 2.5–4.0s | 60–96 |
| 全景（环境） | 3.0–4.0s | 72–96 |
| 空镜（纯环境） | 2.0–3.0s | 48–72 |

**单镜不超过 5 秒**，这是 Wan2.2 单次生成的上限（121 帧）。要更长的镜头，拆成两镜同机位接起来——但接缝会被看出来，所以更好的办法是**改分镜，别做长镜头**。
