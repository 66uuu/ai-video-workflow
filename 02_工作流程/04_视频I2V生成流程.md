# 04 · 视频 I2V 生成流程（图生视频）

> 这是整条链最关键的一段，也是翻车最多的一段。
> 核心不是"让画动起来"，是**让画在几秒内做完一件说得清的事，然后停住**。

---

## 一、模型与参数（不改）

```json
{
  "unet": "Wan2.2-TI2V-5B-Q5_K_M.gguf",
  "clip": "umt5-xxl-encoder-Q4_K_M.gguf",
  "text_encoder_type": "wan",
  "vae": "wan2.2_vae.safetensors",
  "width": 512,
  "height": 768,
  "steps": 24,
  "cfg": 5.0,
  "shift": 8.0,
  "sampler": "euler",
  "scheduler": "simple",
  "fps": 24
}
```

### 节点图（8 个节点，顺序固定）

```
UnetLoaderGGUF (Wan2.2-TI2V-5B-Q5_K_M.gguf)
    ↓
ModelSamplingSD3 (shift=8.0)
    ↓
CLIPLoaderGGUF (umt5-xxl-encoder-Q4_K_M.gguf, type=wan)
    ↓
CLIPTextEncode (正向)  ┐
CLIPTextEncode (负向)  ┤
    ↓                  ↓
Wan22ImageToVideoLatent ← LoadImage (首帧)
    ↓
KSampler (euler / simple / steps=24 / cfg=5.0)
    ↓
VAEDecode
    ↓
CreateVideo (fps=24) → SaveVideo (format="mp4")
```

**两个坑：**

1. `SaveVideo` 的输入是 **VIDEO 类型**，必须前置 `CreateVideo`。`SaveWEBM` 的输入才是 IMAGE。
2. `SaveVideo` 的 `format` 是动态下拉框（DynamicCombo），API 里**必须传字符串** `"format": "mp4"`。传 dict 会被校验层吃掉，报 `SaveVideo.execute() missing 1 required positional argument: 'format'`。

## 二、四段式提示词（可选结构，非强制）

正文**只有四段**，顺序固定，用空格连起来，最后由程序统一追加"机位固定不动"。

```
action + sound + music + lens + 「机位固定不动。」
```

### 段一 · `action` —— 能做完的动作

```
夜，一名女子站在台阶上，把手机贴在耳边等着，身体几乎不动。
她缓慢地低下头，把手机往耳朵上贴紧一点，停住。
```

写法要点：
- **先给静态状态**（她站在哪、在干什么），**再给一个变化**（低头、贴紧、停住），**最后给终止**（停住）
- 用"缓慢地""极轻地"控制速度
- **结尾必须有"停住/停下/不动了"**

### 段二 · `sound` —— 声景

```
雨持续落在水泥台阶和铁皮雨棚上，远处有车驶过积水的声音。
```

Wan2.2 不出声，但写声景有用：**它会影响画面节奏**。写"雨持续落"模型给的画面会更稳、更慢；写"急促的脚步"画面会变快。

### 段三 · `music` —— 配乐

```
无配乐。
```

本剧多数镜头用"无配乐"。写了"紧张的弦乐"模型会在画面上加不稳定感——如果你要的正是那种不稳定，就写；不要就留空。**配乐是自由项，没有统一要求。**

### 段四 · `lens` —— 焦距 + 景别 + 景深

```
近景，85mm 中长焦，浅景深。
```

用真实摄影术语。Wan 对 `85mm 中长焦`、`浅景深`、`微距` 这类词有明确响应。

### 尾部追加（程序统一做）

```
机位固定不动。
```

## 三、三条禁令（每条都是实测翻车换来的）

### 禁令一：不许写画风

❌ `厚涂插画风格，黑暗电影感，青绿冷调`

**为什么不行**：首帧图已经定了画风。文字再写一遍，会和图打架，结果是**画风漂移 + 画面变糊**。

画风在生图提示词里按需写（想写什么风格就写什么风格），I2V 里一个字都不提。

### 禁令二：不许写长相、服装、姓名

❌ `林砚，黑色微卷中短发，右眉尾有疤，橄榄灰米色风衣`

**为什么不行**：首帧图已经把这些信息给足了。文字再描述一遍，模型会在"按图"和"按字"之间摇摆，**结果是换脸**。

实测：写了"短发"，模型把及肩的头发变短了；写了"风衣"，衣服颜色偏了。

**这条最反直觉** —— 越详细的描述，出来的越不像。因为模型把文字当成"要修改的地方"。

### 禁令三：不许写微表情、不许写第二个运镜

❌ `她眼眶慢慢红了，同时镜头缓缓推近`

**为什么不行**：
- **微表情**（眼眶红、嘴角抽动）在 512×768 下分辨率不够，做出来是糊的
- **第二个运镜**会让模型自己发挥大幅度运动，**人直接走出画面**

实测：S20A 第一版写了"镜头极缓慢地向前推近"，Wan 理解成"大推镜"，第 4.9 秒人出画，末帧变成地面特写。

**运镜只允许一个，而且"机位固定不动"这个已经由程序默认给了。** 真要推拉，用 `NR_KenBurns` 后期做，不要在 I2V 里要。

## 四、动作预算（这一节最重要）

**在写提示词之前，先在脑子里过一遍时长。**

| 动作 | 大概需要 | 说明 |
|---|---|---|
| 眨眼 | 0.2s | — |
| 转头 45° | 0.8–1.2s | — |
| 低头 | 0.6–1.0s | — |
| 抬手到胸前 | 1.0–1.5s | — |
| 站起 | 1.5–2.0s | — |
| 走 1 米 | 1.4–1.7s | 常速 |
| **走过整个画面（约 3 米）** | **4.5–5.5s** | ⚠️ 危险 |
| 开门 + 进门 + 关门 | 3.5–4.5s | ⚠️ 危险 |

### 判断标准

> **动作耗时 ≤ 镜头时长的 60%**

留 40% 给"起势"和"收势"。一个 2.5 秒的镜头，动作只能占 1.5 秒。

### 真实翻车案例：S24A

**第一版**：

> 夜，一名中年男子从画面右侧走过，走向画面左侧。

3 秒的镜头，塞了"走过整个画面"。结果：**老周 5 秒走出画面，末帧只剩空停车场**。

**修复版**：

> 夜，一名中年男子侧身从画面右侧走过来，肩膀擦过画面边缘，头低着，视线向下，
> **在画面右三分之一处停住**。

结果：PASS。末帧主体仍在画，左右边带方差 36.19 → 31.14（仍在画）。

**规律**：把"走过去"改成"走进来一点点然后停住"。宁可只给半个动作，也不要在几秒里塞一整套。

## 五、提交方式：队列独立于脚本

**这是本链路最实用的一点。**

```bat
源机器E盘ComfyUI\venv\Scripts\python.exe batch_local.py --submit-only
```

`--submit-only` 只做一件事：把所有镜头的任务压进 ComfyUI 队列，然后立刻退出。

**压完队列后，ComfyUI 自己跑，跟脚本断不断开没关系。** 你可以关掉终端、关掉我、关掉电脑桌面上的任何东西（只要 ComfyUI 服务不关）。

事后来收：

```bat
源机器E盘ComfyUI\venv\Scripts\python.exe batch_local.py --collect
```

### 断点续跑

`video_i2v/S<id>_i2v.mp4` 已存在的自动跳过。所以：
- 中途崩了，重跑 `--submit-only` 会只提交剩下的
- 想重做某一镜，加 `--force` 或 `--only S13`

### `batch_local.py` 参数

| 参数 | 作用 |
|---|---|
| 无参数 | 提交 + 等待 + 收片（一次跑完） |
| `--submit-only` | 只压队列，立刻退出 |
| `--collect` | 只收片（读 `_submitted.json` 里的 prompt_id） |
| `--only S13,S20A` | 只做指定镜 |
| `--force` | 已存在的也重做 |
| `--list` | 只列出清单，不执行 |
| `--seed 20261018` | 指定种子 |

提交记录在 `video_i2v/_submitted.json`，存 prompt_id，收片时按 id 去 `/history` 里取。

## 六、自动质检（G5 / G6）

**不靠眼睛判断"动没动"。** 眼睛会被误导 —— 画面里的雨在动、光在闪，看着像在动，其实主体是静止的。

`_qa_check.py` 算两个数：

### G5 · 真运动判据

```python
# 相邻帧差均值
adjacent_diff = mean(|frame[i+1] - frame[i]|) for i in range(n-1)
# 首末帧差
endpoint_diff = mean(|frame[-1] - frame[0]|)

PASS 条件：adjacent_diff >= 0.30  and  endpoint_diff >= 1.5
```

| 数值 | 含义 |
|---|---|
| 相邻差 < 0.30 | 几乎是静帧（模型没动） |
| 相邻差 0.3–2 | 正常轻微运动 |
| 相邻差 > 8 | 运动剧烈，可能失稳 |
| 首末差 < 1.5 | 结束时回到了开始（动作没完成） |

### G6 · 出画检测

```python
# 左右各取 12% 宽度的边带，算方差
left_band_var  = var(frame[:, :int(w*0.12)])
right_band_var = var(frame[:, int(w*0.88):])

PASS 条件：末帧边带方差 < 首帧边带方差 × 0.55
```

**为什么用边带**：主体在画面中央时，边带是背景（有纹理、方差高）。人走出画面后，边带变成纯色墙/地面/天空（方差骤降）。

实测数据：

| 镜 | 首帧边带 | 末帧边带 | 判定 |
|---|---|---|---|
| S24A（修复后） | 36.19 | 31.14 | ✅ 仍在画（86%） |
| S24A（修复前） | — | 极低 | ❌ 人走了 |

## 七、实测性能基线（RTX 4060 Laptop 8GB）

| 配置 | 耗时 | 显存峰值 |
|---|---|---|
| 512×768 / 72 帧 / 24 步 | **286 秒** | 6.4 GB |
| 512×768 / 121 帧 / 24 步 | **572 秒** | 7.3 GB |
| 512×768 / 60 帧 / 24 步 | 约 240 秒 | 6.2 GB |

不 OOM。可用显存 7.2GB（常驻占 0.9GB），121 帧时峰值 7.3GB 已接近上限但能跑完。

**降级阶梯**（万一 OOM）：

```
帧数 121 → 72 → 48
步数 24 → 20 → 15
分辨率 512×768 → 448×672 → 384×576
精度 Q5_K_M → Q4_K_M
```

一次只降一档，降完必须重跑质检——降太多画面会糊到不能用。

## 八、完整的一次操作

### 准备

1. 关键帧图放进 `07_成片/EP04/shots/EP04/`
2. 在 `SHOTS_EP04.json` 里写好这镜的四段式提示词
3. 确认 `EP04_timeline_v2.json` 里有这镜的 `frames`

### 执行

```bat
:: 方式一：全自动（提交+等待+收片）
双击 一键生成EP04.bat

:: 方式二：压队列就走
源机器E盘ComfyUI\venv\Scripts\python.exe batch_local.py --submit-only
```

### 收片

```bat
源机器E盘ComfyUI\venv\Scripts\python.exe batch_local.py --collect
```

输出：

```
[S01] ⏭ 已收
[S03] ✅ 72帧 | 相邻0.58 | 首末6.16 | 在画
[S16] … 还在排队/渲染
--------------------------------------------------------------------
已收 1 / 未完成 10 / 失败 0
```

那一行 `相邻0.58 | 首末6.16 | 在画` 就是质检结果，不用另外跑。

### 失败处理

| 现象 | 原因 | 修法 |
|---|---|---|
| 人出画 | 动作幅度超预算 | 缩小动作 + 加"在画面 X 处停住" |
| 几乎不动（相邻差 <0.3） | 动作写得太含糊 | 给一个明确的、可见的变化 |
| 换脸 | 提示词写了长相/服装 | 删掉所有外貌描述 |
| 画面变糊 | 提示词写了画风 | 删掉所有画风词 |
| 首末差 <1.5 | 动作做了一半又回去了 | 加终止词"停住" |
