```
阶段 0（新增）：用户想法 → prompt-optimizer 优化 → 8 条铁律注入 → ComfyUI 就绪提示词包
                                    ↓ 喂给 ⑥ 和 ⑦
```

| 项 | 内容 |
|---|---|
| 干什么 | AI 写提示词靠现场发挥，需求丢失严重；改用 prompt-optimizer 引擎先优化再产出 |
| 产出 | `positive` + `negative` + `frames` + `params` + `notes` 五字段提示词包 |
| 喂给谁 | ⑥ 关键帧（生图，进 `IMAGES.json`）、⑦ I2V（进 `SHOTS_EP04.json`） |
| 怎么做 | `15_提示词工程_prompt-optimizer/01_从想法到提示词_SOP.md` 六步 SOP |
| 模板覆盖 | 引擎 19 个模板：7 通用（视频向）+ 12 图像专用（图片向），**图片+视频两类需求全覆盖**，定制见 `15_.../02_模板适配_图片与视频场景.md` |

## 一、总链路（九段）

```
① 故事梗概
② 分集大纲        ← 索引层：60 集各讲什么
③ 分集细纲        ← 执行层：六段节拍 + 必说台词（这一段不能跳！）
④ 分镜脚本        ← 镜号 / 时长 / 景别 / 内容 / 台词
⑤ 时间轴           ← 帧级：每镜起帧止帧，总帧数校验
⑥ 关键帧           ← 每镜一张首帧图
⑦ 图生视频         ← 首帧 + 动作提示 → 视频
⑧ 配音 + 音效      ← 台词 TTS + 声景
⑨ 合成交付         ← 统一规格 + 拼接 + 音轨 + 打包
```

**③ 不能跳过。** 从 ② 直接跳到 ④ 是所有 AI 漫剧翻车的起点：大纲只有"林砚去档案库查人"，分镜却要写"她手指停在第三排第七个抽屉"。中间那层"她为什么来、带什么情绪、说到哪句话时手停住"不在细纲里，分镜就只能靠猜，猜出来的镜头必然空。

## 二、每一段的输入输出

### ① → ② 故事梗概 → 分集大纲

| 项 | 内容 |
|---|---|
| 输入 | 一句话设定 + 世界观 |
| 输出 | 60 集，每集 50–80 字 |
| 关键 | **每集必须有一个"看得见的东西"**，不能是"她意识到……"这种心理描述 |
| 本剧做法 | 每集必有一件实物或一个数字：13 路站牌、6 小时录音、3:14 停摆的表 |

**大纲写"她陷入怀疑"是废的；写"她把计价器按停，数字还涨了 0.4 公里"才是镜头。**

### ② → ③ 分集大纲 → 分集细纲

| 项 | 内容 |
|---|---|
| 输入 | 该集 50–80 字大纲 |
| 输出 | 六段节拍表 + 必说台词 |
| 关键 | 六段时长固定，不许自由发挥 |

**六段节拍（本剧标准，60 集统一）**

| 段 | 时长 | 功能 |
|---|---|---|
| 冷开场 | 3s | 给一个不对劲的细节，不给解释 |
| 情境 | 9s | 交代时间地点人物，让观众安顿下来 |
| 异变 | 23s | 规则第一次显形 |
| 规则触发 | 20s | 主角按规则行动（或违反） |
| 反转 | 20s | 信息重排，前面的细节换一个意思 |
| 新钩子 | 15s | 本集结束，下一集的问题冒头 |

合计 90s，加片头片尾约 91–95s，正好是竖屏短剧的黄金长度。

### ③ → ④ 分集细纲 → 分镜脚本

| 项 | 内容 |
|---|---|
| 输入 | 六段节拍表 |
| 输出 | 每段拆 3–6 镜，全集约 24–32 镜 |
| 关键 | 每镜只做一件事 |

分镜表必须有的字段：

```
镜号 | 时长(s) | 景别 | 机位 | 画面内容 | 动作 | 台词 | 备注(举证镜/留白/复用母版)
```

**"画面内容"与"动作"必须分开写。** 前者是静态构图（她在车里，右手在方向盘），后者是这几秒内发生的变化（她抬眼看向后视镜）。混在一起写，到了 I2V 环节就没法翻译成提示词。

### ④ → ⑤ 分镜脚本 → 时间轴

| 项 | 内容 |
|---|---|
| 输入 | 分镜表 |
| 输出 | CSV + JSON，每镜精确到帧 |
| 关键 | **总帧数必须等于各镜帧数之和，一分不差** |

这一篇单独展开：`03_帧数图与时间轴流程.md`。

### ⑤ → ⑥ 时间轴 → 关键帧

| 项 | 内容 |
|---|---|
| 输入 | 每镜的"画面内容" |
| 输出 | 每镜一张首帧图，1024×1536（或 512×768 直出） |
| 关键 | 关键帧就是这镜的 0.00s，构图必须能撑住后续动作 |

这一篇单独展开：`02_AI分镜图流程.md`。

### ⑥ → ⑦ 关键帧 → 视频

| 项 | 内容 |
|---|---|
| 输入 | 首帧图 + 四段式提示词 + 帧数 |
| 输出 | mp4，512×768，无音轨 |
| 关键 | 动作幅度必须能在时长内做完 |

这一篇单独展开：`04_视频I2V生成流程.md`。

### ⑦ → ⑧ 视频 → 配音

Wan2.2 不出声。台词全部走 TTS 后期贴。

这一篇单独展开：`05_声音与配音流程.md`。

### ⑧ → ⑨ 全部素材 → 成片

这一篇单独展开：`06_合成与交付流程.md`。

## 三、两条并行线

真实做的时候不是一条直线，是三条线在跑：

```
剧本线：③细纲 → ④分镜 → 台词表        （前置，不依赖 GPU）
资产线：角色锚点 → 三视图 → 表情差分 → 场景母版 → 九宫格机位板
                                                        ↓
影像线：⑤时间轴 → ⑥关键帧 → ⑦I2V → ⑧配音 → ⑨合成
```

**资产线必须先于影像线。** 没有角色锚点就出不了三视图，没有三视图就没有稳定的脸，没有稳定的脸整集演员都在换人。
本剧的教训：`CH_ARCHIVIST` 一个角色锚点没做，直接卡死 8 个镜头。

## 四、每一段的质量门

这是从 shuohao-skills 的 18 道确定性质量门里挑出适用于本剧的 7 道。**任何一门不过，不许往下走。**

| 门 | 位置 | 判据 | 不过怎么办 |
|---|---|---|---|
| G1 | 细纲 → 分镜 | 六段节拍齐全，每段有可拍摄的具体动作 | 回细纲重写 |
| G2 | 时间轴 | 帧数之和 == 总时长的帧数，误差 0 | 改时间轴，不改总时长 |
| G3 | 关键帧 | 与角色锚点同一张脸（肉眼看即可判定） | 重出，不许"差不多" |
| G4 | 关键帧 | 画面内无中文/数字文字（后期贴字） | 重出或擦除 |
| G5 | I2V | 相邻帧差 ≥0.30（确实在动）且首末帧差 ≥1.5 | 重写提示词 |
| G6 | I2V | 末帧主体未出画（左右边带方差 < 首帧 55%） | 缩小动作幅度 |
| G7 | 成片 | 每镜时长与时间轴差 ≤1 帧 | 重新裁切 |

G5/G6 的数值由 `_qa_check.py` 自动算，不用眼睛判断。

## 五、最容易被忽略的四件事

**1. 中文文字一律留白**
生图阶段要求画面里没有中文、没有数字、没有招牌字。出来后人工贴字。原因：AI 出中文必是乱码，且乱码在竖屏特写下极其明显。
涉及：寻人启事、里程数、计价器、站牌、涂鸦、讣告、笔记本字迹、录音笔时长。

**2. 一次性外景不新建母版**
本剧 60 集，场景母版 52 张已经够用。出现新外景时标【复用】，挂已有母版改置景，不新建。新建一次就是几百张图的工作量失控。

**3. 每集一红**
每一集必须有一个红色物体，且这个红色必须是叙事信号（不是装饰）。EP04 的红是档案袋上的红笔圈。

**4. 导演主张"没看清"**
恐怖来自信息差，不是血浆和突脸。运镜以静为主。EP04 一共 24 个镜头位，一半是完全固定的。加速快切只留给第三幕。

## 六、这个流程的产能

单机（RTX 4060 Laptop 8GB）实测：

| 环节 | 单件 | 一集（31 镜） |
|---|---|---|
| 关键帧 | 8 秒 | 4 分钟 |
| I2V | 286 秒（72 帧） | 2.5 小时 |
| 合成 | — | 2 分钟 |
| **合计** | — | **约 2.5–3 小时/集** |

挂着跑即可，不需要人守着。60 集约 150–180 小时纯机器时间。

这是"能跑"的数字。要"跑得好"，前面剧本和资产的功夫是省不掉的——那部分才是决定片子好不好的地方，GPU 只负责执行。
